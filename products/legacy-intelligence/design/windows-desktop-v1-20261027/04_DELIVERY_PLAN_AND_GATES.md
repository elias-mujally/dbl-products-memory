# خطة التنفيذ والقبول والمخاطر

[الفهرس](README.md) · [المعمارية](03_ARCHITECTURE_DECISION.md)

## شرائح صغيرة؛ لا يبدأ أي منها بهذا التقرير

| الشريحة | نطاقها | معيار الخروج | التوقف والتراجع |
| --- | --- | --- | --- |
| D0 — بصرية | ثلاثة اتجاهات لـOverview/Items/Import بنمطين وبيانات اصطناعية معلنة | اختيار المالك واحدًا؛ مراجعة J1–J5 وحالات الفراغ والخطأ والنتيجة غير المحسومة | تعديل التصميم فقط؛ لا كود محرك أو SDK |
| D1 — تقنية | غلاف Electron وNode مستقل في مجلد جديد؛ readiness وقراءة fixture عبر AppService | Standard/offline، تحميل DLL، رفض handshake خاطئ، عشرة اختبارات IPC عدائية، ميزانية موارد مقاسة | فشل ABI أو الميزانية يوقف التوسع؛ لا تغيير Preview1 |
| D2 — قراءة | نظرة عامة وأصناف وتفاصيل وبحث وصفحات وسياق لقطة | J1 بلا CLI، لوحة مفاتيح ومظهران؛ الصفحات ثابتة مع تغير head | خلط شركة أو لقطة أو ثقة يمنع التقدم |
| D3 — استيراد | حوار ملف وبصمة مستقلة وفحص وrefreshV1File فقط | صحيح/مكرر/قديم/جزئي/خاطئ؛ تحقق الأثر بعد reopen وتمييز فشل ما بعد commit | لا إعادة آلية عند unknown؛ حفظ الأدلة وفحص الحالة |
| D4 — تقرير وتعافٍ | HTML ونسخة DBL وفحص واستعادة إلى مقصد جديد وسجل منقح | تطابق نتائج API، رفض XSS، استعادة بلا overwrite وقراءة تاريخ بعد reopen | لا تنظيف أو إتلاف أصول عند فشل التحقق |
| D5 — تغليف وقبول | مرشح DBL.exe مستقل وبصمات واضحة | Windows نظيف مدعوم، حساب عادي، مسار عربي ومسافات، Defender وسياسة أصالة، مشغّل بشري جديد | لا تجاوز أمني أو نشر عام تلقائي |

هذه تبعيات ترتيب، وليست تفويضًا لتنفيذ السلسلة. D0 تحتاج اعتمادًا بعد التقرير، ثم D1 لتأهيل قرار التقنية. توسعة تاريخ V1 أو عقود IPC تعرض كمراجعة محددة، ولا تمر ضمنيًا تحت «واجهة فقط». Catalog اختياري منفصل ويتطلب قرار اعتماد الفروع؛ لا دمج هنا.

## معايير قبول مقترحة — كلها NOT EXECUTED في هذه المهمة

| ID | الاختبار | النجاح المطلوب |
| --- | --- | --- |
| A01 | تشغيل من Windows نظيف بحساب عادي | DBL.exe بلا Terminal/JSON أو runtime خارجي ولا UAC روتيني |
| A02 | العمل غير المتصل | أصول وعمليات محلية، ولا طلبات خارجية في السيناريوهات المختبرة |
| A03 | عائلة الحالة والشركة | رفض خلط V1/Catalog أو الشركة/الحقبة في المحرك |
| A04 | عينة مخبرية مأذونة | خمس أصناف: 30/3/50/2/12 بقيمة 1470 ثم 29/3/50/2/12 بقيمة 1450؛ ليست بيانات عميل |
| A05 | الدقة المالية | decimal ووحدة وعملة وسياق صحيح؛ لا فقد دقة أو FX ضمني |
| A06 | ملف مكرر أو قديم أو خاطئ | لا مضاعفة أو تراجع current، مع إثبات بعد reopen |
| A07 | صفحات وقارئ وكاتب | context ثابت؛ cursor متلاعب أو من شركة أخرى مرفوض، بلا فقد/تكرار |
| A08 | غياب Catalog وعودته | notObserved لا حذف/صفر؛ لا حالة عودة دون تاريخ مقبول؛ synthetic فقط |
| A09 | عشر حالات IPC عدائية على الأقل | رفض sender/operation/حقول/حجم/مسار/token مزور؛ لا SQL/FS/shell عامة |
| A10 | XSS وRTL | النص المستورد لا ينفذ محتوى أو أوامر؛ الرمز والقيمة السالبة لا يتبدلان |
| A11 | فشل الحفظ أو انقطاع العامل | الحالة ضمن ضمان المحرك، وUI لا يخفي unknown/needs-attention أو يعيد تلقائيًا |
| A12 | تقرير ونسخة واستعادة | تحقق manifest وفتح مقصد مستقل؛ لا overwrite أو تغيير ERP |
| A13 | الوصول | J1–J5 بلوحة مفاتيح وNarrator والنمطين والتكبير/DPI؛ لا فعل مقصوص |
| A14 | الخصوصية | DTO وسجل مشترك بلا أسرار أو raw أو مسارات خاصة؛ فحص ACL لا يصلحه |
| A15 | الحزمة والـABI | إصدارات مترابطة وDLL سليمة وبناء موثق؛ رفض mismatch |
| A16 | ميزانية أداء مبدئية | على 4 GiB و2 vCPU متفق عليهما: عشر تشغيلات؛ p95 جاهزية≤8s، رد UI≤100ms، صفحة50≤500ms؛ خمول مجمع≤600MiB وذروة≤900MiB للعينة |
| A17 | سياسة حماية وتوزيع | Defender/أصالة وتوقيع حسب قرار المالك، بلا استثناءات أو elevation لتجاوز حاجز |
| A18 | قبول بشري مستقل | ≥4 من5 مهام أساسية دون معرفة التحقيقات؛ 100% من التأكيدات المؤثرة صحيحة، مع تسجيل الغموض |

A16 أهداف قياس للمراجعة، وليست أرقام أداء مثبتة. تقاس كل عمليات العرض والمحرك وحالة الجهاز والـfixture. فشلها قد يبرر تحسينًا أو تجربة Tauri محدودة؛ لا بناء إطارين افتراضيًا. ألف صنف Catalog اصطناعي ليس benchmark لألف صنف بمخزون، ولا يرفع حد 1000 أو يؤهل 5000.

لا تدعي هذه الخطة مقاومة فقد الطاقة الفعلي أو rollback بعد استعادة backup قديم. نجاح مشغّل وكيل سابق يختلف عن قبول بشري مستقل، ونجاح توافق Windows 10 لا يؤهل مرشح Desktop الجديد.

## المخاطر مرتبة

| الأولوية | الخطر | المعالجة |
| --- | --- | --- |
| P0 | عرض بيانات غير مؤهلة كحقائق حية | الوقت والنطاق والثقة والتغطية من المحرك؛ مصدر R3 يبقى غير مؤهل |
| P0 | خلط main وDraft C1 والأرصدة | عائلات ومساحات ومهايئات منفصلة؛ لا دمج أو ترقيات ضمنية |
| P0 | صلاحيات broker أو مستخدمين وهمية | allowlist وتحقق فعلي؛ تقييم بمشغّل واحد، لا RBAC من إخفاء زر |
| P1 | ABI وأمان runtime | Node مستقل وقفل إصدارات ومراجعة أمن وتجربة Windows |
| P1 | ACL وDefender والأصالة | بوابات مستقلة؛ لا إصلاح أو استثناء آلي |
| P1 | إلغاء أو فشل بعد commit | حالات نتيجة صريحة وقراءة إعادة فتح واستعادة منفصلة |
| P1 | واجهة تعمل لكن المصدر أو قيمة العميل غير مثبتة | تأهيل المصدر والقبول البشري والتجاري مسارات مستقلة |
| P2 | حجم وذاكرة وصيانة | قياس D1 قبل توسيع الشاشات؛ تحديث يدوي متحقق لاحقًا |
| P2 | تسمية backup المحلي تعافيًا شاملًا | نسخ مشفر خارج المضيف واسترجاعه مشروع منفصل |

## قرارات المالك المطلوبة

1. اعتماد النطاق والترجيح المشروط ثم D0 فقط؛ المظهر النهائي يختار بعد النماذج.
2. موافقة D1 على التبعيات وأدوات البناء والـruntime المحددة في بيئة تطوير معزولة؛ لا تثبيت الآن.
3. تحديد Windows 11 x64 نظيف مدعوم ومرخص للتأهيل؛ لا VM أو ترقية تلقائية.
4. اعتماد أي توسعة AppService/IPC وعلاقة فروع C1 قبل تنفيذها؛ لا دمج هنا.
5. موافقة استخدام الأدلة المخبرية المحفوظة في E2E إن لزم، والتوقيع والتوزيع الخاص/العام كل على حدة؛ لا خزنة أو عميل ضمن التصميم.

**الخطوة التنفيذية الواحدة التالية:** D0 للأصناف وسياق اللقطة والاستيراد ببيانات اصطناعية، وثلاثة اتجاهات Light/Dark. معيارها اختيار واضح ورحلة مفهومة بلا CLI وبلا تضليل الثقة. بعدها D1 تثبت التكامل والـABI والذاكرة قبل التنفيذ الكامل.
