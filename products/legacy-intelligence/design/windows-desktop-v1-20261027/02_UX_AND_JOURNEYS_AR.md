# تجربة المستخدم والشاشات والرحلات

[الفهرس](README.md) · [نطاق القدرات](01_CAPABILITIES_AND_SCOPE.md)

## ما يريد المستخدم إنجازه

المالك يريد معرفة ما يستحق الانتباه ووقت البيانات وحدودها. المحاسب يريد تتبع الرقم إلى لقطة ودليل. الموظف المخول يريد تحديث ملف وفهم نتيجة الحفظ دون أوامر. هذه شخصيات تصميم، وليست صلاحيات دخول منفذة.

نقترح ست وجهات: **نظرة عامة، الأصناف، اللقطات، التقارير، مركز البيانات، الإعدادات**. سجل العمليات داخل مركز البيانات، والنسخ والاستعادة داخل الإعدادات. تظهر الوظائف المتاحة فقط؛ السبب واضح عند عدم التأهيل، دون حشد صفحات «قريبًا».

## هيكل وتجربة مؤسسية

نافذة Windows بإطار وأزرار نظامية أولًا، تنقل يمينًا، عنوان وفعل رئيسي واحد لكل مهمة، ومحتوى واسع للجداول. شريط سياق دائم يوضح مساحة العمل ومصدرها ووقت اللقطة ووسم «اصطناعي/عينة ERP/تاريخي». معرفات اللقطة والبصمات في التفاصيل عند الحاجة.

نبني على اتجاه PR #13: كحلي هادئ وأسطح واضحة وفعل بترولي، دون زخرفة تخفي الأرقام. مقترح Light: خلفية #F4F7FA، سطح #FFFFFF، نص #152536، فعل #0B6570. مقترح Dark: خلفية #0D1621، سطح #142332، نص #EDF3F8، فعل #6DD4D3. هذه tokens مرشحة، لا قياس تباين جديد أو مظهر نهائي معتمد.

Segoe UI وخط النظام أساس أولي؛ لا تنزيل خطوط. نص أساسي 16 logical px وجدول 15، أوزان 400/600 وشبكة مسافات 4/8/12/16/24/32. أيقونات محلية من مكتبة تراجع رخصتها ووصولها لاحقًا؛ لا Emoji كبديل لأيقونات مؤسسية. اختيار Light/Dark/النظام محلي ولا يعدّل HTML أو بصمات Preview1.

RTL بنيوي يشمل ترتيب DOM والتركيز وCSS logical properties. الأكواد والبصمات والتواريخ الآلية والقيم السالبة داخل bidi isolation باتجاه LTR. لا تتغير هوية الصنف بسبب العرض. أرقام 0–9 مقترحة أوليًا، مع العملة والوحدة صريحتين. الحسابات تبقى decimal strings؛ لا FX أو منطقة زمنية مخترعة.

## لغة الثقة والخطأ

نعرض أربعة محاور مستقلة: نوع الدليل، وقت البيانات، تغطية الميزة، ونتيجة العملية. اللون وحده لا يكفي. تسجيل معطل حاليًا لا يمحو حقيقة قبول لقطة تاريخية صحيحة، ولا يجعلها بيانات حية.

- «هذه عينة اختبار محفوظة؛ لا اتصال حي بنظام ERP».
- «لم يظهر الصنف في هذا الاستخراج؛ لا نستنتج حذفه أو تصفير رصيده».
- «لم تتغير آخر لقطة محفوظة» فقط عندما يؤكد المحرك عدم الحفظ.
- «قد يكون الحفظ اكتمل؛ افحص حالة العملية قبل إعادة المحاولة» عند نتيجة غير محسومة.
- «المبيعات غير متاحة لهذا المصدر» بدل بطاقة صفر.

Loading يعرض مرحلة معلومة دون نسبة مصطنعة. Empty يفرق مساحة فارغة عن بحث بلا نتائج أو ميزة غير مدعومة. Error يحفظ سياق آخر قراءة ويبين قدمها. التنبيه المؤثر يبقى ظاهرًا، لا toast يختفي.

## الرحلات

**J1 — المالك:** تشغيل DBL.exe → اختيار مساحة أو مثال اصطناعي → قراءة نوع البيانات ووقت اللقطة → فتح صنف وتفسيره → إنشاء تقرير. لا Terminal أو JSON أو اسم قاعدة مطلوب لإكمال الرحلة.

**J2 — المشغّل:** اختيار ملف بحوار Windows → اختيار مقيد من broker → تحقق من شروط المصدر وبصمة مرجعية مستقلة → ملخص أثر → تأكيد → مهمة متسلسلة → حُفظت/أعيد الملف/حُفظت مع متابعة/غير محسوم → قراءة تؤكد النتيجة. حساب hash الملف وحده لا يثبت أنه مصدر موثوق.

**J3 — المحاسب:** فتح لقطة محددة عندما تدعمها الخدمة → مقارنة داخل المصدر والشركة والحقبة نفسها → رؤية إضافة/تعديل/غير مشاهد دون حذف. تبقى الصفحات على اللقطة المثبتة إن تغير head؛ يظهر «تتوفر لقطة أحدث» بفتح صريح.

**J4 — التعافي:** إنشاء نسخة DBL بوجهة خاصة مستقلة → تحقق وبصمة → اختيار مقصد جديد → تأكيد أثر → استعادة وفحص وفتح المساحة المستعادة. لا استبدال الأصل أو نسخ ERP أو ادعاء تشفير/تعافٍ خارج المضيف من backup الحالي.

**J5 — الرفض:** شركة أو عائلة حالة خاطئة أو مصدر غير مؤهل → سبب واضح وخطوة ممكنة، دون «قبول على مسؤوليتك». تفاصيل تقنية منقحة عند الطلب، لا أسرار أو stack traces في المسار العادي.

## الوصول والمراجعة البصرية

نستهدف 1280×800 و1366×768 و1920×1080 ونافذة 960×640؛ DPI ‏100/125/150/200% وتكبير نص 200%. تطوى التفاصيل عند الضيق ولا تقص أزرار التأكيد. اختبار Tab/ShiftTab وEscape حيث آمن، تركيز واضح، Narrator وforced-colors وreduced-motion. هدف WCAG 2.2 AA حيث ينطبق؛ تباين النص العادي 4.5:1 والكبير وحدود الإدراك 3:1، مع فحص فعلي لاحق.

D0 المستقبلية تقدم ثلاثة اتجاهات للمراجعة: مساحة عمل مؤسسية، جدول محاسبي كثيف، ومسار مهام مبسط. يختار المالك اتجاهًا قبل البناء. لم نولد صورًا أو مكونات أو نموذجًا في هذه المهمة؛ هذه مواصفات وليست واجهة محققة بصريًا.
