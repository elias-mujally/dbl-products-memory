# Phased Implementation Roadmap

2026-10-25 · **خطة غير منفذة؛ بدء كتابة التطبيق/التثبيت لاحقًا يحتاج الموافقة** · [المخاطر والقرارات](07_RISKS_AND_DECISIONS.md).

لا تقدير زمني قطعي قبل تجربة المعمارية ومعرفة الفريق. نفضل شرائح وظيفية صغيرة، مع حالات اصطناعية جديدة، دون إعادة كتابة المحرك أو مخطط التخزين. ERP و Preview1 والخزنة خارج التنفيذ.

| المرحلة | الناتج | معيار الخروج المقترح | الموافقة المطلوبة |
| --- | --- | --- | --- |
| P0 — الحالية | الوثائق والمقارنة والميزات والمخاطر | ربط كل وعد بقدرة أو فجوة، و Draft PR بلا كود | مراجعة الاتجاه والنطاق؛ لا بدء برمجة |
| P1 — حسم معماري | غلاف محدود و broker ومحرك Node خارجي، read/doctor/status اصطناعي | runtime/ABI صحيح، رفض IPC غير المسموح، لا rendererNode أو شبكة تطبيق، وقياسات جميع العمليات | إطار مبدئي، قائمة SDK/dependencies، جهاز ومجلدات قبل install/build |
| P2 — UX اصطناعي | اختيار اتجاه مرئي ثم ترحيب/مساحة/لوحة/جدول/أخطاء بالمظهرين | RTL ولوحة مفاتيح وضيق/DPI/تكبير وفهم المصدر والوقت؛ لا features وهمية | اعتماد الاتجاه ونطاق النموذج؛ لا قراءة حالة تشغيلية أو ERP |

## ترتيب التنفيذ

ابدأ بمسار قراءة لا import، ثم UX اصطناعي، ثم كتابة واحدة مع readback. لا P3 قبل إثبات حدود P1 وفهم P2. تجربة Tauri بديلة فقط إذا أظهرت P1 سببًا مقاسًا للتحول وموافقة نطاقه. لا تحسين رسوم أو AI قبل اكتمال مصدر/حفظ/تعافٍ واضح.

P0 لا يتضمن scaffold أو package.json أو framework install أو engine refactor أو تغيير حماية. قرار موافقة المؤسس على وثائق التخطيط يختلف عن تفويض تجربة P1 المحددة.

## الاختبارات اللازمة لاحقًا

| المحور | حالات قبول ذات معنى |
| --- | --- |
| العقد والأمن | channel أو sender/frame غير صحيح، unknownkeys، payload ضخم، token قديم/لغرض آخر، traversal/UNC/reparse، executable بديل، NODE_OPTIONS ملوث، اسم صنف يحتوي HTML/XSS، navigation وشبكة مرفوضان |
| صحة البيانات | check لا ينشئ حالة، expectedHash مستقل، تغير الملف بين preview/import، مصدر غير مؤهل يرفض، decimal/currency/غياب مقابل صفر، لا استنتاج مبيعات من الصرف |
| التكرار والترتيب | doubleclick لا يستورد مرتين؛ samefile=replayed بلا لقطة؛ knownold لا يرجع current؛ unseenolder يتوقف؛ كل البطاقات من snapshot واحد؛ مقارنة scope مختلف ترفض |
| الأخطاء والحياة | busy و JSON غير صالح و exit1/2 و childcrash وفشل كتابة/مساحة في fixture، إغلاق النافذة، outcome غير محسوم بلا retry؛ فحص بعد إعادة الفتح |
| النسخ والاستعادة | manifestpin خاطئ، وجهة موجودة/متداخلة، WAL غير هادئ، ملف غير متوقع؛ لا repair/cleanup؛ restore جديد ثم current/history/audit عبر عمليات جديدة |
| UX والوصول | Light/Dark/forced-colors، RTL/LTR، Tab/Narrator،200%text/DPI، ضيق ومتعدد الشاشات، حالات ليست باللون فقط، HTML في متصفح حقيقي |
| التشغيل | Windows x64 مدعوم و Standard بلا Node/npm/Codex مثبتة، أصول محلية، قياس حجم وذاكرة وذروة، حماية وتواقيع وسياسة تشغيل منفصلة |

اختبارات UImock ليست اختبار محرك حقيقي، و E2E اصطناعي لا يؤهل مصدر عميل. إعادة استخدام نسخ المصادر الثلاثة المصرح بها لاحقًا ليست استخراج ERP جديدًا. لا اختبار قطع طاقة على الحالة الناجحة، ولا مساواة process interruption بتأهيل power-loss.

## أول نسخة Desktop للمراجعة

مرشح تقييم خاص بإصدار جديد، يتيح مهام DBL على ملفات مؤهلة جاهزة دون CLI. يبقى جمع ملف المصدر متطلبًا خارجيًا معلنًا؛ لا نخفيه خلف زر ERP غير مثبت. لا تنزيل runtime أثناء التشغيل، ولا إصلاح صلاحيات أو اتصال سحابي أو اعتماد مصدر عام. تقدم الواجهة تعليمات حفظ الأدلة والتوقف عند الغموض.

Definition of done لاحقًا: حزمة وبصمات ونتائج اختبارات محددة وقبول مستخدم ومصفوفة بوابات محدثة. ظهور شاشة أو نجاح devserver/installer لا يحقق ذلك. لا دمج أو نشر عام دون تفويض.
