# DBL Windows Desktop — حزمة الاكتشاف والمعمارية والتصميم

2026-10-25 · **PROPOSED / AWAITING FOUNDER REVIEW** · وثائق فقط؛ لم تُكتب واجهة أو تُثبت اعتماديات أو يُعدّل المحرك أو Preview1.

اعتمد المؤسس اتجاه Windows Desktop محليًا، والعربية و RTL، والوضعين الفاتح والداكن، والخصوصية وسلامة ERP. لم يعتمد إطارًا أو تنفيذًا. الجمهور: المحاسب، مالك الشركة، المدير. الهدف هو فهم بيانات محفوظة موثقة من واجهة واضحة دون أوامر طرفية في تشغيل DBL؛ استخراج المصدر المؤهل ما زال إجراءً خارجيًا بمساعدة المالك، وليس زر اتصال ERP جاهزًا.

## التوصية التنفيذية

**اقتراح Electron + React + TypeScript مع محرك Node/SQLite خارجي محدود الأوامر**. يقلل اختلاف لغة الربط عن المنتج الحالي ويوفر عرضًا محليًا ثابتًا. نعترف بكلفة Chromium ووجود runtime محرك منفصل؛ لا ندعي أفضلية ذاكرة مقاسة. Tauri خيار معتبر إذا أثبتت تجربة لاحقة مكسبًا فعليًا بعد احتساب Node و WebView2 والتوزيع دون إنترنت. WPF بديل أصلي معتبر لفريق C#؛ WinUI3 مقارن أيضًا. لا اختيار نهائي ولا اعتماد إصدار مكتبة في هذه الوثيقة.

التجربة المقترحة تتمحور حول **مساحة عمل → ملف موثق → لقطة محفوظة → تفسير التغير → تقرير وتعافٍ**. يبقى وقت المصدر ونطاقه ظاهرين. لا يعني فتح التطبيق أن البيانات حية، ولا تعني قيمة المخزون ترحيلًا محاسبيًا نهائيًا.
