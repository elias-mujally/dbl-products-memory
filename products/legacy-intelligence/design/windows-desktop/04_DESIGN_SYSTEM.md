# Design System Proposal — DBL Desktop

2026-10-25 · مقترح اتجاه بصري، ليس هوية معتمدة أو واجهة منفذة/مختبرة. [المتطلبات](02_UX_REQUIREMENTS.md) · [التدفقات](03_SCREEN_MAP_AND_FLOWS.md).

## اللغة البصرية

اتجاه «وضوح مؤسسي هادئ»: أسطح محايدة، لون بترولي للأفعال، كثافة عملية للجداول، عناوين عربية واضحة، واستخدام محدود للزخرفة. لا نصوص تسويقية ضخمة أو بطاقات KPI بلا مصدر. نحتفظ بعنوان DBL النصي مؤقتًا؛ لا شعار/أيقونات مصطنعة أو هوية نهائية. الاختيار البصري النهائي يحتاج مراجعة المؤسس ونماذج لاحقة معتمدة.

نستهدف WCAG2.2AA للنص والعناصر القابلة للتطبيق: نص عادي 4.5:1، نص كبير 3:1، وحدود/حالات إدراكية 3:1. اختيار أهداف أوسع للتركيز لا يعني تصنيف معيار AAA على أنه AA. لكل حالة لون مع شكل/عنوان. [مراجع الوصول](09_SOURCES_AND_VERIFICATION.md#accessibility).

## الخطوط والأرقام

Segoe UI الموجود في Windows هو الأساس الأول المقترح مع system-ui ثم Tahoma كبديل، مع فحص اتصال العربية وتشكيلها بالأحجام الفعلية؛ لا ننسخ ملفات خطوط Microsoft إلى الحزمة. خط عربي مضمّن لاحقًا، مثل Noto Sans Arabic، يحتاج قرارًا وفحص ترخيص وتغطية وحجم؛ لا تنزيل أو اعتماد الآن.

مقياس نص مقترح بوحدات logical: عنوان صفحة 28/سطر 40، عنوان قسم 20/30، نص أساسي 16/26، جدول 15/24، مساعد 14/22؛ أوزان 400/600. لا يعتمد التفريق على وزن لا يدعم العربية جيدًا. الأكواد والبصمات يمكن عرضها بخط monospace محلي داخل مساحة LTR دون جعل أسماء الأصناف monospace. لا يصغر النص الطويل لحد غير مقروء؛ يسمح بالالتفاف أو تفاصيل كاملة.

الواجهة تعرض أرقام 0–9 مبدئيًا للمقارنة مع SKU والبصمات مع تنسيق عربي مسمى وإظهار SAR صراحة؛ اختيار شكل الأرقام قرار مؤسس مفتوح. لا تحويل DecimalString إلى floating point للحساب، ولا فواصل/تقريب يغيران الأصل. يتم عرض الدقة/الوحدة المتاحة، والقيم الكبيرة/السالبة تُختبر. التاريخ المعروض يحدد المنطقة الزمنية، ووقت SQL التجاري دون offset لا يُلصق به توقيت مخترع.

## RTL أصيل

- اتجاه الهيكل RTL، الشريط يمينًا وبداية القراءة يمينًا، وعناوين/محتوى عربي وليس نسخًا مترجمة من تخطيط LTR.
- CSS logical properties للمسافات/الحدود ومحاذاة start/end؛ نختبر layout لا نعكس الصور/المخططات كلها آليًا.
- SKU و SHA وامتداد الملف والتاريخ الآلي وأجزاء المسار داخل bidi isolation باتجاه LTR؛ عرض «الاسم/المصدر» عربيًا مع كشف النص الكامل دون قطع مضلل.
- ترتيب DOM/الوصول يطابق القراءة، لا نعالج المشكلة بتغيير بصري فقط. مفاتيح الأسهم في الجدول والتبويبات تتبع نمطًا متسقًا وتُختبر بالعربية/الإنجليزية.
- تعكس أسهم الرجوع/التقدم الدلالية عند الحاجة، ولا تعكس رموز الحفظ/التكبير أو دلالة صعود القيمة. قيمة مقارنة−20 تحتفظ بإشارتها ولا تبدو 20−.
- اختلاف اتجاه عنوان/رمز صنف لا يغير الهوية المخزنة؛ الأسماء نصوص غير موثوقة، وتُظهر محارف اتجاه مشبوهة في التفاصيل عند الحاجة دون تعديل المصدر.

## المسافات والمكونات

شبكة 4logicalpx؛ spacing4/8/12/16/24/32؛ padding صفحة 24(16 في العرض الصغير)، فجوة بطاقات 16؛ radius8 للتحكم و 12 للبطاقات، ظل خفيف للحوارات فقط. صف جدول افتراضي 48 و compact40 مقترح؛ العنصر التفاعلي الأساسي 40 عالٍ وأيقونةزر 32×32 على الأقل، أكبر للمس. لا تصغير لمجرد استيعاب صفوف أكثر.

| المكون | السلوك المقترح |
| --- | --- |
| أزرار | primary واحد واضح لكل خطوة؛ secondary للتراجع الآمن؛ danger فقط لأثر حقيقي وليس مجرد رسالة خطأ. Enter لا ينفذ استعادة عرضًا |
| بطاقة مؤشر | عنوان/قيمة/عملة/لقطة/وقت/تغطية ثم «كيف حُسب؟»؛ لا مؤشرات مبيعات وهمية |
| جدول | رأس ثابت عند تمرير الجدول، اسم/رمز ثم كمية/تكلفة/قيمة، فرز مسمى واتجاهه، حالة تحديد وفوكس ظاهرة. لا تحويل كامل الجدول إلى scroll ثنائي غير مفهوم |
| فلاتر | شريط بحث مع label، عدد نتائج وإعادة ضبط؛ الفلتر لا يبدّل workspace أو snapshot |
| حوار | عنوان فعل وأثر ومساحة/وجهة محددة؛ trapfocus و Escape وتحويل التركيز بعد الغلق. لا إغلاق مهمة كتابة مع وعد تراجع |
| حالة/تنبيه | عنوان مختصر ثم ماذا حدث/هل حُفظت بيانات/الخطوة التالية، مع code اختياري. التحذير الدائم المهم ليس toast يختفي |
| حقل بصمة | expected و computed مسميان، LTR مع التفاف ونسخ صريح، إظهار عدم التطابق دون الاعتماد على اللون |
| رسم | نقاط رصد أو أعمدة مع جدول بديل، مصدر ونطاق، لا أسهم/منحنى يوحيان بتنبؤ؛ palette مراجعة لعمى الألوان |
| تعليمات خصوصية | نص أثر ملموس قرب تصدير/نسخة، لا جملة «بياناتك آمنة» بلا اختبار |

اختيار مكتبة أيقونات/مكونات React مؤجل لفحص الوصول و RTL والترخيص. يمكن تقييم Fluent UI React كاتجاه Windows؛ ليس اعتمادًا أو تثبيتًا. لا أيقونات من Emoji أو رسومات مرتجلة، ولا يضاف CDN.

## الحجم وإمكانية الوصول وحالات العرض

أهداف الاختبار المقترحة:1280×800 و 1366×768 و 1920×1080، ونافذة 960×640 مع شريط مطوي وتفاصيل كصفحة بدل عمود؛ هذه وحدات تخطيط مرجعية وليست حدًا أدنى مضمونًا.100/125/150/200%DPI وتكبير نص/واجهة حتى 200%، وتعدد الشاشات. عندما تضيق نافذة أكثر: أولوية الوقت/الحالة ثم المحتوى؛ تنقل/أفعال لا تُقص، وتمرير جدول مقصود لا فقد أعمدة صامت.

Tab/ShiftTab وتركيز مرئي لا يحجبه رأس ثابت، روابط تخطي، أسماء أزرار، aria-live للنتائج دون تكرار، headings/landmarks دلالية، واختبار Narrator. احترم forced-colors و reduced-motion؛ انتقالات قصيرة اختيارية، ولا وميض أو pulse دائم. لا ادعاء وصول قبل اختبار شاشة فعلية ولوحة مفاتيح وقارئ شاشة.

Loading يعرض المرحلة بلا نسبة مزيفة؛ Empty يشرح سبب الفراغ؛ Error يحافظ على السابق مع بيان أنه قديم/غير متحقق؛ Success يوضح اللقطة/الأثر؛ Partial/Unavailable يختلفان عن 0. اختيار Dark/Light لا يغير التقرير HTML المثبت أو بصمته؛ تنسيق تقرير جديد ثنائي المظهر مرحلة مستقلة لاحقًا.
