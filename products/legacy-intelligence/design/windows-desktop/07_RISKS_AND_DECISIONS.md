## التبعيات وتكلفتها

تبعيات جديدة مقترحة لا مثبتة: إصدار Electron مدعوم، React/TypeScript وأداة بناء واختبار، مكتبة مكونات/أيقونات/رسوم محلية مُراجعة، ووسيط بروتوكول. تبعيات محرك محفوظة: Node22/native ABI127، better-sqlite3، SQLite وصيغة الحالة؛ أحدث patch/security support لم يُؤهلا لهذه الواجهة. أي تحديث أمني لازم ينتج مرشحًا منفصلًا ولا يكتب فوق Preview1.

التكلفة ليست حجم EXE فقط: توقيع الكود وتوزيع خاص، Windows مرخص ومدعوم للاختبارات، وقت فحص Native DLL/Defender، وصول/RTL، دعم المستخدم، وصيانة Chromium/Node/.NET/Rust وفق الاختيار. لا افتراض بشراء شهادة أو جهاز أو اشتراك. لا رسوم أو جدول زمني مُختلق؛ تُحدد الميزانية بعد P1 ومهارات الفريق.

لا يُختار framework أو icon/font license من مظهره فقط. نراجع licenses/notices/SBOM، سلسلة البناء ونسخ الأدوات. ملفات الخطوط النظامية لا تُوزع كأصول للبرنامج دون حقوق مستقلة. لا اتصال سحابي أو update feed أو crash upload ضمن الأساس المقترح.

## قرارات المؤسس المطلوبة

| القرار | اقتراح للمراجعة | ما لا تعنيه الموافقة |
| --- | --- | --- |
| D01 — الإطار المبدئي | Electron + React + TS مع Node منفصل، وتجربة P1 قبل ADR نهائي | ليس ترخيصًا لتركيب SDK أو اعتماد أداء/أمن غير مقاس |
| D02 — أول نطاق | Desktop تقييم خاص لعينة Motakamel V1؛ جميع البيانات الموسومة اصطناعية | ليس منتجًا عامًا أو اتصالًا مباشرًا أو دعم Ibdaa |
| D03 — منصة التأهيل | Windows11 x64 بإصدار/edition مدعوم و Standard account؛ Windows10 توافق legacy فقط | ليس ترقية ERP أو توصيله بالإنترنت أو إثبات ترخيص حالي |
| D04 — اللغة والمظهر | العربية مكتملة أولًا؛ بنية i18n من البداية؛ Light/Dark والنظام؛ أرقام 0–9 مقترحة | ليس وعد ترجمة إنجليزية كاملة أو هوية بصرية نهائية |
| D05 — التوزيع | مرشح خاص مستقل الإصدار، أصول محلية وتحديث يدوي مصرح؛ قرار portable/installer بعد القياس | ليس نشرًا عامًا أو installer ضروريًا أو auto-update |
| D06 — الخصوصية | فحص جاهزية بلا إصلاح ACL؛ synthetic-only حتى إغلاق البوابات؛ لا telemetry | لا تمنح الواجهة حق إدارة أذونات أو خزنة أدلة |
| D07 — تجربة المستخدم | اعتماد بنية «لقطات موثقة» والشرائح الوظيفية، ثم اختيار اتجاه بصري من نماذج لاحقة | ليس بدء كتابة الواجهة أو تغيير المحرك الآن |

يمكن اعتماد الاتجاه والنطاق الآن ثم تفويض تجربة P1 محددة لاحقًا بقائمة اعتماديات وجهاز ومجلدات وقياسات؛ لا نطلب موافقة عند كل تفصيل عادي داخل نطاق تنفيذي سيُعتمد. أي migration أو إعادة هيكلة واسعة أو تشغيل مصدر عميل يتطلب قرارًا مستقلًا.

## أسئلة مفتوحة لا تؤخر إعداد الوثائق

مهارات الفريق المتاحة فعلًا في TS/Rust/C#؟ ميزانية الذاكرة/الحزمة المقبولة على جهاز العميل؟ اشتراط قارئ شاشة/تكبير أو لغات أخرى؟ طريقة حصول المحاسب على بصمة المصدر المستقلة؟ آلية ثقة/توقيع وتحديث دون إنترنت؟ هل أول نسخة مجرد تقييم V1 أم تعميم مصدر لاحقًا؟ متطلبات الاحتفاظ والدعم وحجم البيانات ومن يملك موافقة التصدير؟

لا تفترض الوثيقة إجابات. الخطوة المعمارية التالية بعد مراجعة المؤسس هي تجربة قراءة آمنة صغيرة، لا installer شامل أو rewrite.
