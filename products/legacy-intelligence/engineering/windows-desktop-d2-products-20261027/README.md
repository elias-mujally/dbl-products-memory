## القرار المعتمد وحدود الاعتماد

وافق المالك على D2 المحدودة بعد قبول إثبات تكامل D1 الاصطناعي، مع إبقاء [A16 في Draft PR25](https://github.com/elias-mujally/dbl-products-memory/pull/25) **BLOCKED_ENVIRONMENT_NOT_QUALIFIED و0/10 قياسات**. هذه موافقة تطوير استثنائية وليست تنازلًا عن بوابة الأداء أو قبول Windows مدعوم أو إعلان اكتمال D1. البناء من main نظيف وقبول Windows والتوزيع والتوقيع والقبول البشري والإنتاج تبقى غير مؤهلة.

المرجع البصري هو الاتجاه الأول «اتزان مؤسسي» في [D0/PR23](https://github.com/elias-mujally/dbl-products-memory/pull/23)، بصمة الصورة F5E0ED3ECD642AFB68AB66090773BD3595D691720230C01E8D9C0F57BB326150. حافظنا على شريط المصدر واللقطة، والجدول والتفاصيل، والشريط الجانبي اليميني، وRTL والفاتح والداكن. هذه ترجمة عملية للاتجاه وليست ادعاء تطابق بكسلي للصورة المركبة.

## ما نُفذ في الشيفرة

شاشة أصناف واحدة، بحث بالاسم أو الرمز بحسب اختيار واضح للحقل، تفاصيل من الخدمة، وصفحات مرتبطة باللقطة والبحث المطبق، وحالات تحميل/لا نتائج/صنف غير موجود/فشل قراءة. عرض وقت اللقطة بتوقيت اليمن UTC+03 مستقل عن وقت الكمبيوتر. لا مخزون أو أسعار أو مبيعات أو استيراد أو نسخ أو شاشات إضافية؛ الأقسام المستقبلية تسميات غير تفاعلية.

البيانات خمسة أصناف SYN-101 إلى SYN-105 بهويات عينة DEMO-101 إلى DEMO-105، واسم شركة ومصدر اصطناعيين معلنين. لا تُعرض تلك الهويات بوصفها مفاتيح ERP ثابتة. كل تشغيل ينشئ حالة DBL اصطناعية قياسية جديدة؛ ليست حالة C1 Catalog ولا قبولًا موثوقًا. تحمل DTOs: synthetic وerpQualified=false وtrustedCatalogAdmission=false. المتكامل غير متصل ولا توجد ملفات أو صفوف ERP في التجربة.

Electron يعرض أصولًا محلية؛ preload بخمسة أفعال قراءة محددة؛ main يتحقق من sender/frame/origin والعقد؛ العامل Node مستقل يستخدم Application Service العام للصفحات والبحث والتفاصيل. لا SQLite أو SQL أو مسارات ملفات أو shell أو IPC عام في renderer، ولا تسجيل مصدر أو قبول أو كتابة ERP. بقي sandbox وcontextIsolation وwebSecurity، ورفض الاتصال الخارجي والنوافذ والـpermissions. لا تبعيات أو تغيير مخطط أو عقود محرك أو حراس V1 أو Preview1.

استخدمنا JavaScript/HTML/CSS الموجودة دون React أو dependency جديدة لهذه الشريحة. نعيد استخدام runtime التطوير المثبت في D1 علنًا؛ لا نسميه build جديدًا من main. واجهة البحث تستخدم contains المطبّعة في محرك الاستعلام؛ ليست OR بين الحقول أو بحثًا لغويًا متقدمًا. حالة البحث المطبق مستقلة عن النص غير المرسل لضمان صحة cursor.

## العيوب والمحاولات التي حُفظت

1. أول تشغيل اختبارات العامل:30 نجاحًا وإخفاق واحد لأن اختبار D1 المنسوخ توقع RSS الذي أزيل من DTO الخاص بـD2. صُحح الاختبار ليثبت غياب الحقل؛ لم تُصنع نتيجة أداء. الجولة النهائية31/31، ولا نجمع الجولات في عدد مضاعف.
2. الجولة الأولى لـElectron وصلت إلى عرض الأصناف والتحقق من السياق وعزل preload، ثم لم يفعّل sendInputEvent زر التفاصيل ضمن المهلة. السبب الدقيق للتركيز أو الإدخال غير مثبت. نُقل تحقق لوحة المفاتيح إلى فحص Computer Use في نافذة أمامية، وأصبح الاختبار الآلي للبيانات يختبر زر التفاصيل مباشرة؛ لا ندّعي أن هذا أصلح لوحة المفاتيح قبل فحصها الفعلي.
3. الجولة الثانية توقفت عند **Current display surface not available for capture**. ليست رسالة رفض صلاحيات ولا دليلًا على سبب compositor محدد. لا تعطيل sandbox أو ACL أو تصعيد أو تبديل runtime لمعالجتها. R3 يسجل progress لكل فحص، ويسجل أي صورة متعذرة منفصلة عن النجاح الوظيفي، دون جعلها visual PASS.
4. مراجعة الشيفرة كشفت تمرير نص بحث لم يُطبق مع cursor بحث سابق؛ كان الحارس سيرفضه بدل نشر بيانات خاطئة. أصلحت الواجهة الفصل بين draft وapplied search، وأضفت حالة native خاصة، دون إضعاف حارس cursor.

الفشل التاريخي لسياق الوكيل عند وصول Electron إلى icudtl.dat محفوظ في D1، ولم تُكرر محاولة إطلاق Electron من ذلك السياق. تشغيل المالك يستخدم نفس SDK والمحرك المعروفين من جلسة عادية غير مرتفعة مع فحص البصمات، بلا تغيير Windows أو Defender أو ACL أو الشبكة أو موارد VM.

## المتبقي قبل التسليم المحدود

تشغيل R3 من جلسة المالك، مراجعة تقريره الفعلي، وفحص صور التطبيق أو تصوير النافذة عبر Computer Use، والتحقق من لوحة المفاتيح والفاتح والداكن والبحث والتفاصيل. يميز السجل بين فحص آلي وComputer Use وقبول بشري؛ لا يكفي ظهور DOM أو نجاح API لإعلان تسليم مرئي.

مسار إعادة الإنتاج والعقود وحدود الحقيبة مذكور في README تجربة المنتج. تبقى binaries وSQLite والإعدادات والمسارات الشخصية والمشغلات الخاصة والسجلات الأصلية خارج GitHub. يمكن نشر صور نافذة التطبيق الاصطناعية فقط بعد مراجعة خصوصيتها وبصماتها. لا يُفتح مخزن الأدلة الخاص، ولا تُنقل أدلة أو قواعد ERP أو Preview1.

التوقف عند أول تجربة أصناف؛ الشاشات الأخرى والاستيراد والاتصال بالمصدر تحتاج نطاقًا ومراجعة مستقلين. هذه المرحلة لا تزيل عوائق هوية المتكامل واكتمال استخراجه ولا تؤهل Trusted Catalog.
