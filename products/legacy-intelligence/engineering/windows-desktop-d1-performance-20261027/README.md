## قرار القبول

لم تُنفذ أي محاولة من محاولات A16 العشر؛ لا توجد نتيجة أداء جديدة أو إخفاق معيار أداء مثبت. المتاح للوكيل لا يمثل Windows مدعومًا بذاكرة4GiB و2vCPU. لا نستبدله بالمضيف أو مختبر Windows10 السابق ولا نغير مواردهما لإنتاج نجاح ظاهري. سُئل المالك عن بيئة مستقلة مهيأة مسبقًا؛ لم تتوفر هوية وإثبات أهلية لها عند إعداد هذا التقرير. هذا لا يثبت عدم وجود VM أخرى.

تفويض المالك يسمح بالقياس والبيانات الاصطناعية ونسخة تطوير معزولة، ويمنع إنشاء VM أو تثبيت متطلبات أو تغيير الموارد والحماية دون تفويض مستقل. لذلك توقف تنفيذ قياسات القبول عند شرط البيئة. لم نكرر Get-VM/CIM المرفوضين أو تجربة Electron المرفوضة في سياق الوكيل، ولم نفتح ERP أو مختبرًا تاريخيًا أو Preview1 أو خزنة خاصة.

لذلك يظل **بناء وتشغيل D1 كاملًا من نواتج main جديدة محجوبًا/غير منفذ**؛ runtime المستخدم فيD1 السابق نُسخ من build تطوير محلي قائم. لم ننفذnpm ci أو تثبيتًا محليًا جديدًا، ولم ننسخdist قديمة ثم نسميها بناءً نظيفًا. لا حاجة إلى دمج سلسلةCatalog أو تغيير مخططات لإثبات هذا الشرط.

## المتطلبات الدقيقة للاستئناف — دون تطبيقها الآن

1. بيئةWindows x64 مستقلة ومصرّح بها، بإصدار مدعوم ومحدّث وترخيص مناسب، على عتاد/مضيف مؤهلين. الخيار المفضلWindows11Pro25H2أو إصدار مدعوم آخر يُتحقق منه وقت التشغيل. لا ERP ولا مختبر تاريخي. تحديد الاسم وطريقة الوصول ثم إثبات الإصدار والـedition/build والمعمارية؛ لا كلمة مرور أو مفتاح تفعيل مطلوب هنا.
2. تخصيص **4096MiB ثابتة و2vCPU**، دونDynamic Memory/ballooning يغير الذاكرة أثناء الاختبار؛ إثبات من مستوىVM وداخل الضيف. حساب عادي وجلسة تفاعلية غير مرتفعة وsandbox طبيعي. لا تكفيtaskset أوحدNodeheap أووجود4GiB حرة على مضيف32GiB. إنشاء/تغييرVM أونقل الحقيبة يحتاج موافقة منفصلة.
3. بيئة بناء منفصلة موجودة أصلًا بتبعيات مقفلة ومعتمدة. نسخة مثبتة من main أعلاه، وفرع D1 كطبقة تجربة فوقه؛ مخرجات جديدة دون dist أو runtime قديم. إذا نقصت تبعيات أو ملفات native يلزم تفويض تثبيت محدد أو ناتج CI مؤهل مستقل، ولا تنزيل أو تثبيت ضمنيًا. أدوات التطوير ليست مطلوبة على جهاز القياس.
4. توثيق سلسلة المصدر→المترجم والإصدارات→المخرجات→runtimemanifest→حقيبة القياس. تثبيتNode22.23.2/ABI127 وnativeSQLite الفعلي وElectron45.0.0 وبصماتها كما فيD1، أوقرار مستقل لأي تغيير إصدار. نقل الحقيبة الجديدة ومخرجاتها بطريقة محدودة معتمدة، دون شبكة المصدر أومشاركة مجلداتERP أوتعطيلDefender/SmartScreen.
5. إتاحة قراءة مقاييس عمليات التجربة فقط بالحساب العادي. إذا تعذرت قراءةPID أوذاكرة، تكون العينةmissing والفحصغيرمؤهل؛ لا صفرًا أوتخمينًا ولا رفع صلاحيات. حفظ أدلة كل محاولة محليًا وبصماتها؛ نشر النتائج المنقحة فقط.

## بروتوكول القياس المحدود عند توفر البيئة

هذا بروتوكول **لم يُنفذ ولم يُبرمج في هذه المهمة**؛ يثبت تعريف القياس لتجنب إعادة تفسير النجاح لاحقًا.

- عشر جلسات تطبيق مستقلة متتابعة، بلا عمليات DBL متبقية، بعينة اصطناعية ثابتة. يسجل أول تشغيل بعد دخول Windows منفصلًا؛ البقية تبدأ عمليات جديدة مع cache النظام الطبيعي. لا ادعاء بتفريغ cache أو تشغيل بقرص بارد. تسجل حالة Windows وDefender والموارد والنشاط المنافس والطاقة وDPI. لا تستبعد المحاولة البطيئة.
- **الجاهزية p95≤8s:** ساعة monotonic من قبل إنشاء العملية إلى نافذة ظاهرة مرسومة وعامل جاهز وفعل قابل للاستخدام، لا وقت loadURL أو main وحده. مع عشر قيم، nearest-rank p95 هو القيمة العاشرة بعد ترتيبها، أي max. الفشل أو timeout لا يسقط أو يستبدل. هذا وصف لعينة صغيرة وليس SLA إنتاجيًا.
- **استجابة الواجهة≤100ms:** من إرسال فعل آمن إلى أول feedback مرسوم، مع فصل تأخر الإطارات وزمن roundtrip للعامل. تُحدد الأفعال والتكرارات قبل التشغيل، وينشر p50/p95/max لكل فعل؛ يُطبق حد100ms على جميع العينات المعلنة، دون تعميم على تفاعلات لم تقَس.
- **صفحة50≤500ms:** عينة اصطناعية من100 صنف مثلًا، لا خمسة، لاختبار صفحتين فعليتين. تستخدم APIs القائمة دون تغيير حراس V1 أو Catalog، وتثبت بصمة العينة وسياق القراءة. تقاس الصفحة الأولى واللاحقة: زمن المحرك والنقل والرسم منفصلة ومجموعها من الطلب إلى العرض. يطبق الحد على العينات المعلنة.
- **الخمول المجمع≤600MiB والذروة≤900MiB:** قراءة متزامنة كل100ms لجميع عمليات التطبيق: main وrenderer وGPU وutility وعامل Node، مع PID ووقت إنشائه. متحكم القياس وVMConnect خارج المجموع ويذكر أثرهما. خمول60s بعد الجاهزية، والذروة على كامل دورة الأفعال حتى الإغلاق. تستخدم واجهة Windows نفسها لقياس working set وprivate committed bytes لكل مكون؛ لا خلط Electron WS مع Node RSS. الذروة هي max عبر الزمن لمجموع العينات المتزامنة، وليست مجموع القيم القصوى المستقلة.
- مجموع working sets قد يحتسب صفحات مشتركة مرتين؛ ينشر بهذا الاسم، ولا يسمى ذاكرة فعلية فريدة. ينشر private committed منفصلًا، واستهلاك Windows الكلي للسياق فقط. نستخدم مجموع WS معيارًا متحفظًا معلنًا، مع حد دقة sampling100ms. إذا قصدت A16 ذاكرة فعلية فريدة فيلزم حسم تعريفها قبل قبول الرقم.
- عدم القدرة على حصر العمليات أو قراءة مقياس يجعل العينة ناقصة، لا صفرًا أو نجاحًا. تحفظ أدلة كل محاولة وفشل وبصماتها دون تنظيف أو إعادة تلقائية. عند إخفاق معيار نحلل أصغر عنق زجاجة ونقترح تعديلًا محددًا، دون تغيير التقنية تلقائيًا.
