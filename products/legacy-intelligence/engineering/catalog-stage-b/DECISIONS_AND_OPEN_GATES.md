## العقد المختار للمراجعة

يتضمن draft format، source instance/company/epoch، نطاق full catalog مع coverage محدد، mapping version، capture ID وsequence وتوقيتين، اكتمالًا صريحًا وcounts/صفحات ونهاية ناجحة وبصمة payload ومفتاحًا ثابتًا لكل صنف. يمنع تغيير النطاق أو epoch أو إعادة استخدام المفتاح بصمت. الشاهد المستقل خارج الملف ضروري؛ حتى الشاهد الموقّع لا يجعل تصديرًا غير متسق مكتملًا بمجرد وجود توقيع.

تفاصيل [العقد في المنتج](https://github.com/elias-mujally/dbl-legacy-intelligence/blob/ecba3c2129488fa98bf88355df560bd2f5becf8f/docs/contracts/FULL_PRODUCT_CATALOG_CAPTURE_DRAFT.md). تمركز تعريفه هناك يمنع وجود عقدين متعارضين. هذه الذاكرة تحفظ قرار الاختيار والدليل والحدود، دون تكرار مواصفة طويلة.

## الفجوات التي تمنع التشغيل

- SourceRef الحالي مغلق ويقبل connectorId/sourceSystem/sourceVersion فقط؛ لا يحمل company/scope/epoch/completeness. لا نضيف حقولًا عشوائية أو نخفيها داخل النصوص.
- لا admission ledger دائمة للـsequence/epoch أو هوية ملف كامل، ولا ترقية ذرية تجمع دليل القبول مع اللقطة/current. قواعد source order يجب أن تتفق مع اختيار latest الحالي المبني على capturedAt.
- لا public historical-by-ID reader أو سجل تغييرات أصناف أو lifecycle للغياب والحذف وإعادة الظهور/الترميز.
- لا parser آمنة للعقد المقترح أو canonical encoding بين اللغات أو إثبات مصدر/اتساق تصدير مؤهل. الشاهد الاصطناعي وحده لا يحمي من ملف وشاهد مزورين معًا.
- لا تأهيل مورّد/إصدار أو مفتاح صنف حقيقي؛ لا مسار SQL مباشر أو منع كتابة خارجي مثبت لهذه المعمارية. علامة readOnly في fixture ليست صلاحية SQL.
- لا قياس حجم/أداء أو crash/concurrency admission أو جاهزية عميل/إنتاج. بوابات Windows المدعوم وDefender وACL والقبول البشري المستقل والنسخ المشفر خارج المضيف تبقى مستقلة.

## ما يحتاج القرار التالي

مراجعة العقد والاختبارات أولًا. ثم، **بموافقة منفصلة**، تصميم المرحلة C لتسجيل المصادر وقبول full capture مع metadata دائمة وترتيب وإعادة محاولة وتعافٍ وترقية current، واختبارات رفض مصدر ناقص قبل أي تغيير. يقرر التصميم هل تكفي الطبقات الحالية أو نحتاج تعديلًا محدودًا للمخطط؛ لا نفترض migration ولا ننفذها الآن.

بعد تأهيل هذه البوابة فقط يأتي تفويض اكتشاف تصدير ERP محدد وإصداره ومفاتيحه وحدود تغطيته بإذن صاحبه. لا تشغيل دوري أو CDC أو شبكة جديدة كاختصار. يستمر تصميم واجهة Windows حول capabilities ومصادر وحالات لقطات عامة، دون ربطها بحارس V1 أو اختراع حالة مزامنة غير منفذة.

يبقى PR14 وPR22 وهذه الملاحظات قيد المراجعة؛ لا يعني نشر Draft PR دمجها أو اعتماد بروتوكول تنفيذي جديد.
