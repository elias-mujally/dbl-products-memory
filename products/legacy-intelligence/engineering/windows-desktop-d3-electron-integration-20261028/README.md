## ما نُفّذ ولماذا

Electron Renderer → preload بخمس دوال فقط → main يتحقق من النافذة/الإطار/الأصل والـschema/الحجم → Node22 مستقل → غلاف PR32 غير المعدل → Application Service → ملاحظة ثابتة لنسخة operator مؤهلة ضمن الملف الاصطناعي.

Runtime جديد يُجمع من المكونات المبنية والمثبتة سابقًا، مع manifest وبصمات، دون تثبيت/تنزيل أو تحديث Runtime قديم أو تغيير أذونات. Native SQLite تُحمّل في Node22 خارج Electron. Runtime الحالي لـD2 لم يكن يتضمن قارئ V1، ومحركه ينشئ عينة عند hello، لذلك لم نستخدمه لفتح مصدر مخزون. ملفات D2 المرجعية وسلوكها لم تتغير.

الخلفية تحتفظ بالمسارات والبصمات والـprofile/verification/internal IDs. الردود العامة تحذفها حتى وإن أبقاها الغلاف الداخلي؛ تبقى رموز تفاعل مبهمة فقط. هذا تضييق عرض معتمد بالتفويض، لا تغيير عقد المحرك أو التخزين. تصنيف v1-lab-capture مرفوض في هذه الشريحة؛ لا يُفعَّل مصدر فعلي بمجرد تغيير path.

## الضوابط المثبتة

- عمليات sources/openLatest/page/detail/close فقط؛ لا SQL/FS أو import/تسجيل/استدعاء عام. فحص المرسل/الإطار وعزل Renderer وCSP وsandbox باقية.
- Request/reply allowlist وحجم8KiB/64KiB؛ أخطاء منقحة؛ لا hash أو مسار أو مرجع تخزين في الرد.
- قراءة ثابتة خمس دقائق، مع بداية زمن محافظة تشمل النقل، وإعادة فتح يدوية. إشعار lifecycle أحادي الاتجاه ليس عملية قراءة سادسة؛ مرتبط بالـreadRef، فلا يمحو مصدرًا أحدث.
- إجمالي كامل من الخدمة لا يتغير مع البحث والصفحة. القيم سلاسل عشرية؛ لا تحويل غياب إلى صفر.
- لا حركات/GL/توقيع/low-stock أو وحدة مخمنة. التاريخ هو الاستخراج، وليس وقت العرض أو مخزون اليوم.
- D2 منفصلة؛ لا join عبرSKU أو استخدام مراجعها لقراءة المخزون.
- جميع حالات الفشل/التحميل تمسح الأرقام؛ سقوط العامل يبطله، ولا يبدأ عامل جديد إلا عند إعادة فتح يدوية.
- اختبارات clock/delay/corrupt-reply خاصة بقناة parent أثناء qualification فقط؛ لا تُتاح للواجهة أو التشغيل العادي ولا تعدّل مصدرًا أو إعدادًا.
