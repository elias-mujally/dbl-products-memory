## القرار وحدود إعادة الاستخدام

مسار مخزون V1 يعتمد مصالحة حركات وتكلفة مدعومة، لذلك لا يُضعف لقبول صنف
بلا حركة. المسار الجديد مستقل لدليل الأصناف فقط: sourceKey/sku/name، وأرقام
المخزون والتكلفة والقيمة غير مكتسبة وتعرض «غير متاح»، لا صفرًا اصطناعيًا.
المفتاح مرصود وليس إثباتًا لثبات i_code عبر إعادة الترقيم أو إعادة الاستخدام.
اختفاء مفتاح سابق يرفض اللقطة بدل افتراض حذف أو صرف.

أعيد استخدام Product وSqliteLocalStore وImportOrchestrator والتدقيق وApplication
Service وقارئ مخزون V1 التاريخي. التغييرات محصورة في تجربة جديدة وCI عام لها؛
لم تتغير محركات أو قواعد V1 أو Preview1 أو الحالات العاملة السابقة.

عامل Node مستقل وElectron sandbox/contextIsolation، مع Renderer بلا SQL أو
ملفات أو مفاتيح أو إعداد اتصال. بوابة IPC تتحقق من العمليات والطلبات والردود.
المصدر الاصطناعي وضع صريح مستقل؛ لا fallback له عند فشل المصدر الحقيقي.
الغلاف الحالي شريحة هندسية ذات تبويبين، لا استبدال لتصميم Workspace الكامل.

## الحفظ والتاريخ والفشل

حالة SQLite جديدة مصدرة بالإصدار، منفصلة عن V1 وCatalog C1 والتجارب السابقة.
طلب عشوائي وnonce وتسلسل وlease، ثم التقاط خارج معاملة النشر؛ تحقق مصدر
وصلاحيات واكتمال وحداثة، وحفظ إيصال كل محاولة متحققة حتى عند ثبات المحتوى.
يبنى مرشح كامل ويعاد فتحه للقراءة، ثم معاملة metadata واحدة للرأس والطلب
وأوقات النجاح وحدث النشر المحلي. الفشل السابق للـcommit يبقي الرأس القديم،
والفشل بعده يعلن الحفظ والحاجة لإعادة القراءة؛ المرشحات والأدلة لا تُحذف.

لا لقطة مكررة عند ثبات المحتوى الحالي. الصفحات والمراجع مرتبطة بلقطة؛
المهلة خمس دقائق. بعد الانتهاء يبقى العرض محفوظًا مؤرخًا مع تحذير وطلب
إعادة فتح، ولا يصبح رصيدًا لحظيًا. D3 مخزون تاريخي مستقل عن دليل D2 الجديد.

الحدود الحالية: ألف صنف، 32 لقطة متغيرة، 128 محاولة، 50 صفًا في الصفحة،
30 ثانية للمصدر و120 ثانية للطلب. لا تنظيف أو توسعة حدود تلقائيًا، ولا دليل
على تحمل فقد الطاقة أو كشف استعادة ERP قديمة ذات المفاتيح نفسها.

## المصدر الحقيقي: محجوب حتى موافقات محددة

المساعد المرشح ثابت للضيف وشركة الاختبار وإصدارها، ويقرأ عمودي دليل الأصناف
فقط بلا فلتر ولا ربط بالحركات. يفحص هوية login/database user والنقل المحلي،
والصلاحيات الفعلية والمنح وأدوار الجلسة قبل/بعد القراءة، ثم COUNT/DISTINCT
والصفوف في SERIALIZABLE واحدة مع rollback. يمكن للقراءة حجز أقفال؛ لم
تُختبر كلفتها أو توافرها فعليًا. الحقول الذاتية في JSON ليست إثبات اكتمال
مستقلًا؛ التنفيذ الموثوق والمصالحة الميدانية مطلوبان.

PowerShell5.1 رفض تجربة -File غير متصلة لأن السكربتات معطلة على المضيف.
لا تغيير ExecutionPolicy أو تشغيل المساعد بصيغة بديلة للتحايل. تحليل AST
بـPowerShell7 بلا أخطاء صياغة ليس إثبات تشغيل PowerShell5 أو SQL.

لم ينشأ حساب SQL أو ملف سر ولم تفتح هذه المهمة اتصال SQL. سياق المصدر
الحقيقي معطل. توافر Shared Memory ووضع المصادقة وشهادة TLS وظهور metadata
لحساب محدود وسياسة الضيف كلها غير مثبتة. فشل أي منها لا يجيز إعدادًا تلقائيًا.

القرار التالي: موافقة منفصلة على فحص جاهزية واتصال metadata محدود لشركة
الاختبار، ثم عرض الإعداد المحدد لحساب لا يملك إلا CONNECT وSELECT على
عمودي الدليل. لا db_datareader/db_owner/sysadmin أو صلاحيات كتابة/تنفيذ،
ولا تغيير public أو TLS/شبكة/خدمات/حماية أو منح أوسع لإرضاء الفحص.
السر محلي بهوية المالك وحماية Windows، لا يرسل إلى Codex أو GitHub.

إذا حُجب المساعد في الضيف، يعرض مسار توقيع معتمد أو مُصدر أصلي .NET في
قرار جديد؛ لم يُبن بديل تنفيذي لتجاوز الرفض. بعد نجاح القراءة المتكررة
والمصالحة، يلزم خط أساس حديث واستعادة تخصه ثم موافقة بطاقة سادسة فقط؛
لا شراء أو بيع أو صرف أو افتتاحي لإظهارها. الضغط على مزامنة وظهورها دون
ملفات وسيطة هو معيار الدورة الحقيقي الذي لم يتحقق بعد.

أدلة المصدر والأسرار والإيصالات والبصمات الخاصة والمسارات الشخصية مستبعدة
من GitHub وCI. CI العام يختبر العقد والنقل الاصطناعي والصياغة فقط، لا SQL
ولا SQLite/Electron المحلي. A16 وNarrator وWindows المدعوم النظيف والصلاحيات
وDefender ونسخ خارج المضيف والتوزيع والإنتاج بوابات مفتوحة.

## فحص الجاهزية المأذون — 2026-11-02

النتيجة الحالية **BLOCKED_CERTIFICATE_TRUST_AND_SCRIPT_POLICY**. سمح المالك
بفحص إصدارات وسياسات واتصال metadata واحد لشركة الاختبار، دون أصناف أو
حساب جديد أو سر أو تغيير إعدادات. نفّذ المالك الفحص يدويًا وأرسل ملخصًا
محدودًا ومرجع الأصل؛ لم يفتح الوكيل الأصل أو يتحقق من بصمته مستقلًا.

المحاولة الوحيدة توقفت في Open أثناء تسجيل الدخول بسبب سلسلة شهادة غير
موثوقة للعميل. queryAttempted=false وqueryCompleted=false؛ لا SELECT أو
مساعد استخراج أو كتابة ERP. لا اتصال مصادق عليه أو تحقق حديث لهوية قاعدة
البيانات. إعداد النقل المحلي والتشفير لا يثبت النقل الفعلي أو نجاح TLS.

البيئة المرسلة: Windows10 Pro build19045.3803، PowerShell5.1.19041.3803
بعملية64bit، و.NET Release528372 الذي يقابل Framework4.8. CLR4.0 ليس نفيًا
لتوافر4.8. سياسة التنفيذ الفعلية Restricted مع Undefined في النطاقات الخمسة.
هذه أدلة بيئة من ملخص المالك، لا تأهيل نظام Windows مدعوم نظيف أو A16.

بقيت engine ووضع المصادقة والنقل الفعلي وعضوية sysadmin ووجود login/user
القارئ جميعها null؛ لم يبدأ الاستعلام. لا نفسر null على أنها عدم وجود حساب
ولا نستبدلها ببيانات تاريخية. لا نعرف شهادة أي جهة قدمت، ولا نجزم بأنها
self-signed أو أن CA بعينها ناقصة دون جرد محدد.

Restricted تمنع ملفات السكربتات؛ توقيع PS1 وحده لا يكفي تحت هذه السياسة.
لم تُحوّل أوامر التشخيص اليدوي المأذونة إلى مسار تشغيل مساعد المزامنة.
لا TrustServerCertificate=True أو Encrypt=False أو TCP fallback أو تغيير
ExecutionPolicy أو CA/ثقة/ACL/Defender/شبكة/خدمات؛ لا إعادة محاولة بعد الرفض.

الخطوة المفضلة المقترحة: جرد ضيق، بموافقة جديدة، لإعداد شهادة المثيل
والـpublic metadata للشهادة المعينة فقط وأحداث Schannel القائمة للمحاولة،
دون SQL جديد أو مفاتيح خاصة أو تصدير أو تثبيت أو اتصال شبكة. الجرد دليل
إعداد وقد لا يثبت الشهادة التي قدمتها الجلسة. لم ينفذ أو يُفوض بعد.

يؤجل إنشاء حساب القارئ حتى فهم الثقة والمتطلبات. تصحيح سلسلة الثقة أو ربط
شهادة أو restart يحتاج خطة وموافقة منفصلتين؛ لا يؤذن به ضمن الجرد. قارئ
أصلي .NET مراجع خيار معماري لاحق يحتاج تفويضًا قبل بنائه أو تشغيله، ولا
يتجاوز الرفض أو يصلح TLS وحده أو يغني عن الحساب المحدود وتأهيل المصدر.

لا تغييرات شيفرة أو Runtime بسبب هذه النتيجة، ولا تأهيل لصنف سادس فعلي.
يبقى نجاح R3 الاصطناعي16/16 وبوابات A16/Narrator/Windows/الإنتاج كما هي.

## جرد الشهادة R1 وحدود الأداة — 2026-11-02

وافق المالك على جرد ضيق بلا SQL أو تغيير حماية، ثم نفّذ R1 وأرسل ملخصها
ومرجع الأصل. النتيجة STOPPED_CERT_INVENTORY_PRESERVE_OUTPUT عند mapping؛
العلامة INSTANCE_MAPPING_KEY_NOT_FOUND صادرة من حارس الأداة بعد null من
OpenSubKey في Registry64. لم ترد رسالة AccessDenied.

لم تصل الأداة إلى قيمة المثيل أو إعداد الشهادة أو مخزنها أو Schannel؛ كل
هذه القيم بقيت مجهولة، وعدد الأحداث ليس صفرًا. لم يحدث SQL أو تغيير، ولم
يفتح الوكيل الأصل أو يطابق بصمته مستقلًا. الأصل والإيصال والبصمة الخاصة
والمسارات والأسماء الداخلية خارج GitHub.

حصر Registry64 قيد تغطية في أداة التشخيص، وليس إثباتًا لغياب SQL أو الشهادة
أو فساد تثبيت. لم نفحص Registry32 ولم نثبت معمارية محرك SQL؛ معمارية Windows
أو PowerShell لا تكفي لاستنتاجها. Windows يوفر عرضين منفصلين لبعض المفاتيح:
[Microsoft RegistryView](https://learn.microsoft.com/en-us/dotnet/api/microsoft.win32.registryview)،
[Registry Redirector](https://learn.microsoft.com/en-us/windows/win32/winprog64/registry-redirector).

حفظت R1. أعدت R2 للتنفيذ اليدوي المعلن باستخدام Registry32 فقط للمفتاح
المنطقي نفسه وقيمة المثيل نفسها، ثم Certificate/ForceEncryption في العرض
نفسه عند وجود mapping مقيد. لا مسارات مادية مخمنة أو عرض إضافي تلقائي أو
تخمين instanceId أو بحث في مثيلات/شهادات أخرى. هذا ليس تجاوز رفض صلاحيات.

الغياب يسجل كحالة غير متاحة، ويتيح استكمال قراءة Schannel المستقلة في نافذة
الدقيقتين المعتمدة السابقة؛ أي رفض وصول أو هوية غير متوقعة أو خطأ آخر يوقف
كل المراحل. لا اتصال يولد أحداثًا جديدة، ولا توسيع نافذة أو فحص مفاتيح خاصة
أو export أو chain-build أو شبكة أو تغيير سياسة أو ثقة أو إعدادات.

نجح تحليل الصياغة ومراجعة النطاق الساكنة لـR2 فقط؛ لم تنفذ من سياق الوكيل
ونتيجتها الميدانية معلقة. مساعد المزامنة وشيفرة المنتج لم يتغيرا، وحجب
ثقة الشهادة وRestricted وعدم تأهيل حساب المصدر مستمران. لا Source/ERP أو
A16 أو Narrator أو Windows مدعوم نظيف أو إنتاج أُهل بهذه الخطوة.


## نتيجة جرد الشهادة R2 الميدانية — 2026-11-02

أرسل المالك تقرير R2 جديدًا وملخصه؛ يختلف عن R1 المعاد إرسالها سابقًا، ولا
تحتسب الرسالة المكررة تنفيذًا آخر. حفظ مرجع الأصل وإيصاله محليًا فقط، ولم
يفتح الوكيل الأصل أو يعِد حساب بصمته مستقلًا.

الحالة COMPLETED_READONLY_INVENTORY_FINDINGS_ONLY. وجد mapping YSEDU ومفتاح
إعداد النقل في Registry32. Certificate موجودة دون بصمة صريحة بعد التطبيع،
وForceEncryption المقروءة0. هذه قيم إعداد، لا قياس النقل أو TLS في جلسة فعلية
ولا إثبات معمارية محرك SQL. لم يُقرأ مخزن الشهادات لأن شرط البصمة لم يتحقق.

اكتملت قراءة أحداث System/Schannel36882 في نافذة UTC المحددة ذات الدقيقتين
وكان matchingEventCount=0. يثبت ذلك عدم العثور على مطابقات ضمن الفلتر فقط؛
لا ينفي خطأ TLS السابق ولا يثبت تعطيل logging أو غياب شهادة. خواص الشهادة
ومصدرها وسلسلة ثقتها وهويتها المقدمة فعليًا ما زالت مجهولة.

لم يحدث SQL أو تشغيل مصدر أو تعديل ERP أو إعداد أو export أو chain-build
أو شبكة. حجب TLS المثبت وRestricted وتأهيل حساب القارئ وهوية المصدر واكتماله
وبطاقة الصنف السادس ما زال مفتوحًا. لا runtime أو شيفرة منتج تغيرت.

غياب البصمة الصريحة متوافق مع شهادة يكتشفها SQL تلقائيًا أو fallback مولدة؛
لا يثبت أي اختيار في V1. توثق Microsoft رسائل سجل بدء SQL عن تحميل شهادة
معينة أو توليدها، لذلك الخطوة التالية المقترحة قراءة ضيقة لسجل البدء وحساب
خدمة المثيل للمساعدة في إعداد خطة ثقة قابلة للمراجعة. لم تنفذ هذه القراءة،
وتحتاج موافقة منفصلة؛ لا اتصال جديد أو توليد أحداث أو تخفيف TLS أو صلاحيات.
[Microsoft: الشهادة وسجل SQL](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/configure-sql-server-encryption)،
[Microsoft: العثور على أثر تحميل الشهادة](https://learn.microsoft.com/en-us/troubleshoot/sql/database-engine/connect/ssl-errors-after-tls-1-2).

جرد البدء المقترح لا يتضمن تثبيت أو إنشاء أو استيراد شهادة، أو قراءة private
key، أو تغيير الثقة/السياسة/ACL أو إعادة تشغيل خدمة، أو بناء قارئ .NET أو
إنشاء حساب SQL. رفض الوصول يوقف العمل ولا يعالج بإصلاح الأذونات أو elevation.
نجاح الجرد الميداني المحدود ليس تأهيل المصدر أو Windows أو الإنتاج.

## نتيجة قراءة بدء SQL المأذونة — 2026-11-02

الحالة التشخيصية **BLOCKED_ACCESS_DENIED_PARAMETERS**. أرسل المالك ملخص
التنفيذ ومرجع الأصل؛ لم يفتح الوكيل الأصل أو يتحقق من بصمته مستقلًا.
نجحت قراءة نوع حساب الخدمة المكوّن فقط، ثم رفض OpenSubKey الوصول صراحةً
عند قراءة معامل مسار سجل البدء. لا ننشر هوية الحساب أو المسارات أو السطور.

لم يُحدد مسار ERRORLOG، ولم تُقرأ منه أي بايتات (sourceBytesRead=0)، ولم
يكتمل فحص السجل. الشهادة المقدمة فعليًا وسلسلة الثقة ما زالتا غير مثبتتين؛
لا استنتاج لشهادة ذاتية التوقيع أو fallback من هذه النتيجة. يختلف هذا الرفض
عن غياب مفتاح Registry64 السابق، ولا يعالج بمحاولة عرض أو مسار بديل.

توقف الفحص عند الرفض دون إعادة أو elevation أو تخمين مسار أو استعمال
هوية الخدمة أو تغيير ACL أو شهادة أو سياسة أو خدمة. لا SQL جديد أو تشغيل
مساعد المصدر أو كتابة ERP أو إعدادات. لا شيفرة منتج أو Runtime تغيرت.

نتائج21/21 السابقة تختبر وظائف نقية وذاكرة اصطناعية فقط؛ لا تؤهل الوصول
للسجل أو تشغيل المساعد في PowerShell5.1. لم تُعد اختبارات الأداء أو المنتج
من أجل تحديث التوثيق. تبقى نتائج R3 الاصطناعية السابقة ضمن نطاقها وحده.

فشل ثقة TLS السابق وRestricted وتأهيل القارئ وهوية المصدر واكتماله وثبات
هوية الصنف والصنف السادس الفعلي جميعها غير مغلقة. لا مصدر ERP مؤهل ولا
مزامنة فعلية مثبتة؛ A16 وNarrator وWindows والإنتاج تبقى مفتوحة.

بديلة؛ لا منح صلاحيات عامة أو تخفيف TLS أو إصلاح أذونات ضمن التفويض الحالي.
