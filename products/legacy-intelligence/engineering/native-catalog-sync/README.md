# المزامنة المحلية عند الطلب — شريحة دليل الأصناف المرصود

الحالة: تطوير واختبارات اصطناعية؛ الاتصال الحقيقي والصنف السادس الفعلي لم
يُثبتا. لا مصدر ERP مؤهل ولا Trusted Catalog ولا اعتماد إنتاجي.

مرجع المنتج: [Draft PR43](https://github.com/elias-mujally/dbl-legacy-intelligence/pull/43)،
فوق [PR42](https://github.com/elias-mujally/dbl-legacy-intelligence/pull/42).
هذه الذاكرة تتراكم فوق PR31؛ لا دمج في main أو أي فرع آخر.

## القرار وحدود إعادة الاستخدام

مسار مخزون V1 يعتمد مصالحة حركات وتكلفة مدعومة، لذلك لا يُضعف لقبول صنف
بلا حركة. المسار الجديد مستقل لدليل الأصناف فقط: sourceKey/sku/name، وأرقام
المخزون والتكلفة والقيمة غير مكتسبة وتعرض «غير متاح»، لا صفرًا اصطناعيًا.
المفتاح مرصود وليس إثباتًا لثبات i_code عبر إعادة الترقيم أو إعادة الاستخدام.
اختفاء مفتاح سابق يرفض اللقطة بدل افتراض حذف أو صرف.

أعيد استخدام Product وSqliteLocalStore وImportOrchestrator والتدقيق وApplication
Service وقارئ مخزون V1 التاريخي. التغييرات محصورة في تجربة جديدة وCI عام لها؛
لم تتغير محركات أو قواعد V1 أو Preview1 أو الحالات العاملة السابقة.

عامل Node مستقل وElectron sandbox/contextIsolation، مع Renderer بلا SQL أو
ملفات أو مفاتيح أو إعداد اتصال. بوابة IPC تتحقق من العمليات والطلبات والردود.
المصدر الاصطناعي وضع صريح مستقل؛ لا fallback له عند فشل المصدر الحقيقي.
الغلاف الحالي شريحة هندسية ذات تبويبين، لا استبدال لتصميم Workspace الكامل.

## الحفظ والتاريخ والفشل

حالة SQLite جديدة مصدرة بالإصدار، منفصلة عن V1 وCatalog C1 والتجارب السابقة.
طلب عشوائي وnonce وتسلسل وlease، ثم التقاط خارج معاملة النشر؛ تحقق مصدر
وصلاحيات واكتمال وحداثة، وحفظ إيصال كل محاولة متحققة حتى عند ثبات المحتوى.
يبنى مرشح كامل ويعاد فتحه للقراءة، ثم معاملة metadata واحدة للرأس والطلب
وأوقات النجاح وحدث النشر المحلي. الفشل السابق للـcommit يبقي الرأس القديم،
والفشل بعده يعلن الحفظ والحاجة لإعادة القراءة؛ المرشحات والأدلة لا تُحذف.

لا لقطة مكررة عند ثبات المحتوى الحالي. الصفحات والمراجع مرتبطة بلقطة؛
المهلة خمس دقائق. بعد الانتهاء يبقى العرض محفوظًا مؤرخًا مع تحذير وطلب
إعادة فتح، ولا يصبح رصيدًا لحظيًا. D3 مخزون تاريخي مستقل عن دليل D2 الجديد.

الحدود الحالية: ألف صنف، 32 لقطة متغيرة، 128 محاولة، 50 صفًا في الصفحة،
30 ثانية للمصدر و120 ثانية للطلب. لا تنظيف أو توسعة حدود تلقائيًا، ولا دليل
على تحمل فقد الطاقة أو كشف استعادة ERP قديمة ذات المفاتيح نفسها.

  **53/53** بلا تجاوز، ومنها التنافس والانقطاع وإعادة الفتح؛ لا دليل حاليًا
  على تراجع المسار المنشور. الفشل السابق محفوظ كخطأ اختيار مرجع قديم.
- رفض استعلام عمليات المضيف عبر CIM؛ لم نرفع الصلاحيات أو نستخدم بديلًا
  لتجاوز الرفض. أوقفت جلسة الاختبار القديمة التابعة للمهمة بعد حفظ فشلها؛
  لا ادعاء بإيقاف عمليات أخرى أو فحص كامل لها.

صور R2 الفعلية روجعت بصريًا: العربية والوسم الاصطناعي وفصل الأرقام غير

RTL يحتاج تحسين عرض لاحقًا. صور وأصول الاختبار محلية ولا تُنشر في الذاكرة.

## المصدر الحقيقي: محجوب حتى موافقات محددة

المساعد المرشح ثابت للضيف وشركة الاختبار وإصدارها، ويقرأ عمودي دليل الأصناف
فقط بلا فلتر ولا ربط بالحركات. يفحص هوية login/database user والنقل المحلي،
والصلاحيات الفعلية والمنح وأدوار الجلسة قبل/بعد القراءة، ثم COUNT/DISTINCT
والصفوف في SERIALIZABLE واحدة مع rollback. يمكن للقراءة حجز أقفال؛ لم
تُختبر كلفتها أو توافرها فعليًا. الحقول الذاتية في JSON ليست إثبات اكتمال
مستقلًا؛ التنفيذ الموثوق والمصالحة الميدانية مطلوبان.

PowerShell5.1 رفض تجربة -File غير متصلة لأن السكربتات معطلة على المضيف.
لا تغيير ExecutionPolicy أو تشغيل المساعد بصيغة بديلة للتحايل. تحليل AST
بـPowerShell7 بلا أخطاء صياغة ليس إثبات تشغيل PowerShell5 أو SQL.

لم ينشأ حساب SQL أو ملف سر ولم تفتح هذه المهمة اتصال SQL. سياق المصدر
الحقيقي معطل. توافر Shared Memory ووضع المصادقة وشهادة TLS وظهور metadata
لحساب محدود وسياسة الضيف كلها غير مثبتة. فشل أي منها لا يجيز إعدادًا تلقائيًا.

القرار التالي: موافقة منفصلة على فحص جاهزية واتصال metadata محدود لشركة
الاختبار، ثم عرض الإعداد المحدد لحساب لا يملك إلا CONNECT وSELECT على
عمودي الدليل. لا db_datareader/db_owner/sysadmin أو صلاحيات كتابة/تنفيذ،
ولا تغيير public أو TLS/شبكة/خدمات/حماية أو منح أوسع لإرضاء الفحص.
السر محلي بهوية المالك وحماية Windows، لا يرسل إلى Codex أو GitHub.

إذا حُجب المساعد في الضيف، يعرض مسار توقيع معتمد أو مُصدر أصلي .NET في
قرار جديد؛ لم يُبن بديل تنفيذي لتجاوز الرفض. بعد نجاح القراءة المتكررة
والمصالحة، يلزم خط أساس حديث واستعادة تخصه ثم موافقة بطاقة سادسة فقط؛
لا شراء أو بيع أو صرف أو افتتاحي لإظهارها. الضغط على مزامنة وظهورها دون
ملفات وسيطة هو معيار الدورة الحقيقي الذي لم يتحقق بعد.

أدلة المصدر والأسرار والإيصالات والبصمات الخاصة والمسارات الشخصية مستبعدة
من GitHub وCI. CI العام يختبر العقد والنقل الاصطناعي والصياغة فقط، لا SQL
ولا SQLite/Electron المحلي. A16 وNarrator وWindows المدعوم النظيف والصلاحيات
وDefender ونسخ خارج المضيف والتوزيع والإنتاج بوابات مفتوحة.

## النتيجة النهائية R3 — تلحق بالنتائج التاريخية ولا تستبدلها

اجتازت الجولة الفعلية **16/16** داخل Electron، بلا فشل، خلال367.36998 ثانية،
بما فيها ست دقائق فعلية ثم انتهاء المرجع وإعادة فتحه. فُتحت عملية مراجعة
جديدة من SQLite المحفوظة؛ أكدت Computer Use النافذة والوسم الاصطناعي ودليل
106 أصناف بلا أرقام مالية، وD3 الاصطناعي المستقل، ثم أعادتها إلى D2 في Light.
التنفيذ بمساعدة المالك ومراجعة الوكيل ليس قبول مشغّل بشري مستقلًا.

راجعت أداة منفصلة ثلاث لقطات5/6/106، وسبعة طلبات (ثلاث applied واثنان
unchanged واثنان failed)، وخمسة أحداث محلية ملتزمة وإيصالات مطابقة، وغياب
كل الحقول المالية، وبقاء أصول stock الاصطناعي دون تغيير. فشلت محاولة التحليل
الأولى لأنها أغفلت WAL عند قراءة ملف التحكم في الذاكرة؛ صححت أداة المراجعة
إلى نسخة تحليل كاملة للملف وWAL، دون فتح الأصول بـSQLite، ونجحت. ليس ذلك
دليل فقدان بيانات؛ فُحص تطابق بايتات الأصل وWAL أثناء مراجعة النسخة.

رأس الشيفرة المختبر `2abb4de7677e73ebf5762b6ae5cc4e738857ed03`: جميع فحوص
CI الأربعة نجحت على Windows وUbuntu. عقد/نقل/Renderer العامة60/60 بلا تجاوز؛
ليست بدلًا عن SQLite/Electron المحلي أو إثبات صلاحيات SQL. أي رأس توثيقي
لاحق منفصل عن رأس الشيفرة. لا تغييرات runtime بعد هذه النتيجة.

القرار: **PASS_SYNTHETIC_INTEGRATION / BLOCKED_REAL_SOURCE_SETUP**. لم تُنقل
هذه الشريحة إلى V1 ولم تُشغل اتصال ERP أو تنشئ الصنف السادس. القرار التالي
المقترح فحص جاهزية V1 بالقراءة فقط؛ يشمل اتصال metadata محدودًا بموافقة
جديدة، ولا يشمل حساب القارئ أو تخزين السر أو تعديل أي سياسة أو بطاقة.
