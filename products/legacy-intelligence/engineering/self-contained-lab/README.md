# المختبر المستقل — تجهيز المزامنة المحلية

الحالة: **PREPARED_SOURCE_BLOCKED**. هذه شريحة نشر وتشخيص، وليست إثبات نجاح
مزامنة ERP. لا صنف سادس أو حركة ERP أو إعداد حساب/شهادة/سياسة ضمنها.

## ما أُعيد استخدامه

- نسخة DBL داخل V1 تعمل على اللقطات الأربع المستوردة سابقًا. شوهدت النافذة
  فعليًا في هذه الجولة؛ لا تعامل بياناتها التاريخية بوصفها قراءة اليوم.
- Runtime Node/Electron/SQLite وApplication Service الموجود في حزمة المختبر.
- مسار native-sync السابق: عامل Node، IPC محدود، تخزين مستقل وتاريخ ومحاولات
  ومراجع قراءة، وبوابة مصدر مغلقة افتراضيًا. لم تتغير ملفات هذا المسار القائمة.
- قارئ V1 التاريخي الصارم للمخزون المحفوظ؛ منفصل عن دليل الأصناف المرصود.

الاستخراج اليدوي السابق استخدم Windows Integrated Security. نجاحه لا يثبت
صلاحيات قراءة فقط أو تحقق شهادة TLS مكافئًا للمسار الجديد. لا يُحوّل إلى
خدمة تعمل دائمًا بهوية واسعة الصلاحيات.

## إضافة النشر المحدودة

`inlab-runtime.cjs` يتحقق من حزمة المختبر الأصلية وملفات overlay وبصماتها،
ثم يستخدم runtimes المحلية نفسها. يمنع UNC والتحويلات ومسارات الهروب، ويثبت
هوية جهاز الاختبار والتشغيل العادي غير المرتفع. يتحقق من نسخة مخزون محفوظة
محددة قبل إنشاء حالة DBL جديدة بجانب النسخة القائمة؛ لا يفتح حالة V1 للكتابة.

جميع مسارات التشغيل والحالة والسجلات داخل الضيف؛ لا خادم مضيف أو مشاركة
شبكة أو تنزيل وقت التشغيل. نقل حزمة التطوير مرة واحدة ليس جزءًا من دورة
المزامنة. تطبيق شرط المسارات والـpins دليل تصميم وتغليف؛ يكتمل إثبات التشغيل
الميداني بعد تشغيل الحزمة داخل الضيف. لم يُثبت استقلال دورة ERP الكاملة بعد.

وضع التشغيل `local-sql-read` مع `source.enabled=false`؛ ليس synthetic-test.
لا تحميل fixture عند فقد المصدر، ولا إنشاء نجاح أو بيانات دليل بديلة.
يُرفض زر/طلب المزامنة غير المهيأ. تشغيل هذا التجهيز لا يصلح TLS ولا يغيّر
Restricted ولا ينشئ قارئًا. تمكين المصدر لاحقًا تغيير إعداد مراجع مستقل بعد
إغلاق بوابات المصدر، وليس خيارًا حرًا في Renderer أو تعديل pin يدويًا.

المخزون التاريخي يبقى كميات وقيمًا مؤرخة. المسار الحي المرشح لدليل الأصناف
يقرأ الرمز والاسم فقط؛ لا يصنع كمية/تكلفة/قيمة ولا يدّعي تحديث المخزون الحي.
`i_code` مرصود ضمن المختبر، وليس هوية ثابتة مؤهلة عبر إعادة الترقيم/الاستخدام.

## نتائج منفذة

- اختبارات الحدود والتغليف العامة: **71/71**، دون تجاوز؛ منها 11 للتغليف
  الجديد و60 اختبارًا سابقًا للعقد والنقل الوهمي والواجهة. لا SQL أو Electron
  في هذه المجموعة، ولا تثبيت تبعيات.
- تحقق التغليف المحلي: 21 ملفًا إضافيًا، والتحقق من343 ملفًا في الحزمة
  الأصلية دون تغييرها. الأرشيف لا يحتوي استخراجات ERP أو بيانات اعتماد.
- عامل Node فعلي منفصل، على نسخ الأدلة التاريخية المحتفظ بها: **27/27**،
  جولتا إغلاق وإعادة فتح، أربع لقطات وقراءة التفاصيل والبحث عبر Application
  Service، ورفض المصدر غير المهيأ دون إنشاء نجاح أو لقطة Catalog. تطابقت
  ملفات المخزون ومرافقاتها قبل وبعد. هذا ليس اتصال ERP ولا اختبار داخل VM.
- نُقل الأرشيف إلى الضيف عبر وسيلة النسخ القائمة، دون تغيير مشاركة أو خدمة.
  تشغيل overlay داخل الضيف والتحقق من إيصالها ما زالا بانتظار نتيجة المالك.

التغليف الأول توقف قبل إنشاء overlay بسبب تفسير خاطئ لمجلد `state` في
manifest المخزون. المحاولة التالية كشفت رفض أسماء npm المشروعة ذات `@`؛
حُفظت النسخة الجزئية، وأُنتجت R2 مستقلة بعد إصلاح الحارسين وإضافة انحدار.
محاولة تقرير اختبارات باسم reporter غير متاح لم تنفذ الاختبارات؛ استُخدم
TAP المدمج دون تثبيت. فحص محدود لعملية الاختبار عبر CIM رفض صلاحيات المضيف؛
لم يُعد أو يُستبدل بطريق وصول آخر، ولم يلزم لإثبات إيصال الاختبار الناتج.

النافذة القديمة بقيت تعرض انتهاء مرجع القراءة بعد محاولة إعادة فتح المحفوظ؛
لا نحسب ذلك نجاح إعادة فتح جديدًا. يلزم التحقق في تشغيل جديد مع سجله، دون
نسبة السبب إلى المحرك أو الاتصال دون دليل. لا استبدال للنسخة القديمة.

## البوابات قبل المزامنة الحقيقية

1. فهم شهادة SQL الحالية وتأهيل الثقة والتحقق من اسم الاتصال والإصدار.
   رفض الوصول السابق إلى Parameters لا يثبت استحالة الاتصال، لكنه يمنع
   استكمال ذلك التشخيص ضمن صلاحياته. لا إعادة أو مسار بديل دون تفويض محدد.
2. سياسة تشغيل مسموحة للمجمع. Restricted لا تسمح بملف PS1 ولو كان موقّعًا.
   أي تغيير سياسة أو ثقة ناشر يحتاج خطة وموافقة؛ لا Bypass/EncodedCommand
   أو نقل المساعد إلى shell/برنامج آخر للتحايل على الرفض.
3. حساب قارئ منفصل مؤهل، وصلاحيات فعلية محدودة ومقارنة إدارية مستقلة.
   إعداد login/user أو DPAPI أو تغيير grants غير منفذ وغير مفوض الآن.
4. تحقق المصدر والاكتمال والهوية واتساق معاملة القراءة، ومصالحة مستقلة
   ضمن شركة الاختبار الحالية. التكرار لا يثبت ثبات المفتاح عبر الزمن.

توصية المسار: تأهيل المجمّع المحلي الموجود ثم إعادة استخدامه. لا فائدة
مثبتة الآن من موصل جديد؛ قارئ .NET بديل لا يصلح الثقة أو التفويض تلقائيًا.
تعديلات الشهادة أو ربطها أو إعادة خدمة قد تؤثر ERP، وتحتاج خطة عودة مستقلة.
[Microsoft: متطلبات شهادة SQL](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/certificate-requirements)،
[Microsoft: إعداد تشفير SQL](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/configure-sql-server-encryption)،
[Microsoft: سياسات PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1).

## توقف R0 ومراجعة حارس PKI — 2026-11-02

أرسل المالك نتيجة STOPPED_CA_READINESS_PRESERVE_OUTPUT عند فحص هوية Cmdlet،
برسالة EXPECTED_BUILTIN_PKI_CMDLET من الحارس المركب في المساعد. تحقق
تطابق الحساب، لكن خصائص الأمر والـprovider والسياسة والخدمة والربط ومتاجر
الشهادات لم تُؤهل. الحقول null مجهولة، وصف ملخص الشهادات الفارغ لا يثبت
أن مخزنًا فُحص. لم يحدث SQL أو شهادة أو private-key access أو تغيير إعداد.
الأصل وإيصاله خاصان؛ لم يفتحه الوكيل أو يتحقق من بصمته مستقلًا.

كشفت مراجعة الكود عيب مقارنة حالة أحرف في ModuleName. أسماء الوحدات في
PowerShell تعامل دون حساسية لحالة الأحرف، بينما استخدم الحارس -cne.
اختبارات معزولة أثبتت رفض اسم pki من القاعدة الصحيحة في الشرط القديم،
وقبوله بعد التصحيح، مع استمرار رفض الاسم الأجنبي أو القاعدة الخارجية.
لا تثبت الاختبارات أن حالة الأحرف هي فرع رفض الضيف؛ R1 لم تسجل metadata
