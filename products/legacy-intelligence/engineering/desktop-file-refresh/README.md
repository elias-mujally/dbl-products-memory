# استقرار Desktop والتحديث اليدوي من ملف — شريحة تطوير مستقلة

التاريخ: 2026-10-30. المرجع: [PR المنتج #41](https://github.com/elias-mujally/dbl-legacy-intelligence/pull/41)، فوق PR #40 عند الرأس `28d4e65e`. لا دمج أو إصدار إنتاجي.

## المشكلة والقرار

كانت نسخة العرض السابقة تمسح الصفحة المقبولة عند انتهاء مرجع القراءة بعد خمس دقائق. بقيت المهلة الأمنية في الخلفية كما هي. يفصل التنفيذ الجديد بين عمر قدرة القراءة وعمر الملاحظة التاريخية التي استلمتها الواجهة كاملة بعد التحقق: تبقى البيانات المحلية مع تاريخها وتحذيرها، وتنتهي القدرة على إجراء قراءة جديدة. انتهاء المرجع أو تعطل العامل لا يجعل البيانات حديثة، ولا يشغّل موصلًا حيًا.

هذا تغيير مقصود داخل تجربة Desktop جديدة فقط. سلوك مسارات D2/D3 السابقة وعقودها لا يتغير. لا تُستخدم سياسة الاحتفاظ الجديدة لتبرير إخفاء فشل قراءة أو عرض بيانات قديمة على أنها صالحة لعملية جديدة. تظهر عبارة تعذر التحقق/انتهاء المرجع بجانب الملاحظة السابقة؛ لا تستبدلها استجابة جزئية أو متأخرة. التفاصيل والبحث يعملان على DTO الصفحة المقبولة نفسها، دون إعادة حساب الإجمالي المالي داخل Renderer.

## البنية

- عائلة حالة Desktop جديدة مع ملف تعريف صريح وقاعدة metadata مستقلة. ليست migration لقاعدة V1 ولا تحديثًا لـPreview1.
- جداول للرأس والأجيال ومراجع اللقطات المستقرة والمعاينات محددة الصلاحية والأحداث المحلية وتفضيلات العرض المقيدة.
- حزم V1 كاملة ومتحقق منها تُنشأ في وجهات جديدة. يُستعاد كل مرشح من آخر حزمة سليمة، ثم يمر بالمستورد والمدقق والنسخ الاحتياطي المعتمدين دون تخفيف الحراس.
- معاملة metadata واحدة تنشر مؤشر الحزمة والمراجع واستهلاك المعاينة وحدث القبول. لا ادعاء بمعاملة واحدة عابرة لملفات قواعد V1 المتعددة.
- فشل ما قبل commit يبقي الرأس السابق. الفشل بعد commit المؤكد يطلب إعادة الفتح بدل ادعاء التراجع. لا تُحذف الحالات المرشحة أو الأدلة القديمة تلقائيًا.
- مقارنة فعلية لكل صفوف التاريخ السابقة قبل النشر، وليس عدد اللقطات فقط. استخراج لاحق بلا تغير أعمال يظل ملاحظة مستقلة. الملف المعروف لا يكرر اللقطة ولا يعيد الرأس إلى الماضي.

أعيد استخدام قارئ V1 وApplication Service والمحرك والمستورد والتحقق والنسخ والاستعادة الموجودة. يجري التشغيل بمحركات مثبتة ببصماتها في نسخ مستقلة؛ لم تُغيّر بنية V1 أو بصمات migrations أو الحزمة المرجعية. إعادة استخدام build محفوظ لا تثبت بناءً نظيفًا من main.

## حدود الواجهة والثقة

قناة جديدة محدودة لعمليات حالة التحديث والتفضيلات واختيار الملف والمعاينة والتأكيد، مع تحقق المرسل والأصل والطلبات والردود. يحول Main اختيار الملف إلى مرجع عشوائي قصير العمر. لا يحصل Renderer على مسار داخلي أو اتصال SQLite أو صلاحية SQL أو قراءة ملفات عامة.

يتطلب الملف الجديد بصمة مستقلة يوفرها المشغل من عملية الاستخراج. يمكن إعادة استخدام بصمة ملف سبق قبوله بعد مطابقة سجل المصادر المحتفظ به. تطابق البصمة مع الملف يثبت سلامة النقل ضمن سلسلة الأدلة، وليس ثبات هوية الأصناف أو اكتمال دليل ERP العام أو تأهيل البائع.

تقول الواجهة «تحديث من ملف استخراج». تاريخ الاستخراج ووقت الاستيراد الناجح وآخر تحقق حقائق منفصلة. توفر استخراج أحدث يبقى «غير معلوم» إلى أن يوفره المشغل. لا شبكة أو جدولة أو اتصال ERP تلقائي.

## الأدلة المنفذة وحدودها

نجحت مجموعة Node الاصطناعية محليًا: **53/53، دون تجاوز**. يتضمن العدد 18 فحصًا موروثًا؛ هذه تغطيات متداخلة وليست مجموعات مستقلة تُجمع مرة أخرى. تشمل المعاينات القديمة والمنتهية والمتغيرة، الشركة الخطأ، زيادة الأصناف خارج النطاق، التاريخ والتكرار، تفضيلات إعادة الفتح، فشل خطوات الكتابة، إنهاء عمليات مستقلة قبل/بعد commit، وسباق كاتبين على الملف نفسه أو ملفين مختلفين. ثبت عدم تغير ملفات الحزمة عند القراءة، ووجود حدث نشر واحد في metadata في اختبار السباق.

نفذ أيضًا اختبار محلي منفصل على الاستخراجات المحفوظة المصرح بها، مع إعادة الفتح وفشل البصمة والتكرار وعدم التراجع. الأرقام والأصول والبصمات والإيصالات والمسارات والصور الخاصة تبقى محليًا، وليست مادة هذا التوثيق. هذا الاختبار ليس استخراجًا جديدًا أو حركة ERP جديدة.

نجحت الجولة الأولى داخل Electron من جلسة المالك العادية 15/15، ومنها ست دقائق زمنية فعلية مع بقاء العرض. حُفظت أدلتها دون استبدال. أضافت R2 تصحيحًا للتمييز بين الحفظ وفشل عرض ما بعد الحفظ، وتصحيح دلالة replay عند خطأ بعد commit، وحالتين إضافيتين للردود المتأخرة وفشل القراءة المحقون. نجحت الجولة النهائية R2 في Electron الفعلي 17/17، ومنها ست دقائق زمنية فعلية دون تجديد المهلة. طابقت ملفات التشغيل الـ13 الرأس البرمجي eb38658a4d21ba00508bf15d8c2855f3e7a7704f، وبقيت أصول المصادر دون تغيير. فُتحت جلسة عادية جديدة ظاهرة من الحالة الدائمة. نجح CI العام وحدود الواجهة على Windows وUbuntu للرأس البرمجي نفسه؛ لا دلالة A16 أو إنتاج. الاختبار يحقن اختيار الملف عند حد نافذة الاختيار الأصلية فقط، وتبقى الواجهة وIPC والعامل والمستورد والتخزين حقيقية. هذا لا يثبت تجربة مشغل بشري لاختيار الملفات يدويًا.

CI العام يشغل حدود الواجهة وفحوص الصياغة على Windows وUbuntu. مجموعة التخزين تحتاج runtime محليًا مصرحًا به؛ تتجاوز نفسها صراحة في CI دون إعداد خاص. لا يُحسب هذا التجاوز نجاحًا للتكامل أو بديلًا عن اختبارات العمليات المحلية.

## حدود مفتوحة وإعادة الإنتاج

النطاق ما زال ملف V1 المحدود الأصناف والفروع والمخزن والوحدة والعملة. لا يدعم إضافة صنف سادس أو Trusted Catalog عامًا. الحراس الحالية وحدود عدد اللقطات والمعاينات محفوظة؛ امتلاء الحد يتوقف دون حذف الأدلة. سياسة دوران الاحتفاظ والتأهيل الأكبر تحتاج عملًا مستقلًا.

إعادة الإنتاج المصرح بها تستخدم مجلد حالة جديدًا، ومحركات موجودة مثبتة البصمات، ونسخة seed مستقلة، ومجلد نتائج منفصلًا. تُشغل اختبارات Node عبر `DBL_REFRESH_TEST_CONFIG` محلي لا يُنشر. يشغل المالك Electron من جلسته العادية مع sandbox، وتبقى الملفات والأدلة الأصلية دون تغيير. لا تعديل ACL أو Defender أو شبكة أو تثبيت تبعيات.

اكتملت دورة التغيير المأذون والاستخراج والنقل والتحقق والاستيراد الفعلي والتاريخ والتكرار وإعادة تشغيل التطبيق ضمن نطاق المختبر المحدود. هذا قبول هندسي محلي للمسار اليدوي، وليس تأهيل مصدر ERP عامًا أو قبول مشغل مستقل أو إنتاج.

تبقى A16 وNarrator وWindows النظيف المدعوم والبناء النظيف والتوزيع والإنتاج وحماية الاحتفاظ خارج المضيف وفقد الطاقة الفعلي غير مؤهلة. لا يغيّر نجاح الاختبارات الاصطناعية حالة المصدر غير المؤهل لـTrusted Catalog.

## قرار المالك بعد التسليم التطويري

وافق المالك على تجربة تغيير مصدر واحدة محدودة داخل شركة الاختبار وV1 فقط، بشرط إثبات خط أساس حديث ووسيلة استعادة تطابقه قبل الحركة. يشمل التفويض قراءات SELECT محدودة واستخراجًا جديدًا موثقًا ونقلًا بالطريقة الحالية، ولا يشمل تغيير الصلاحيات أو الإعدادات أو الشبكة. أي نسخة أو تجربة استعادة جديدة تُعرض بمساراتها ونطاقها قبل التنفيذ. نفذ المالك فحص preflight للقراءة فقط داخل الضيف، ونُقلت نتائجه بالطريقة القائمة وطابقت بصماتها المستقلة. تحقق المسار المعتمد محليًا من خط الأساس المحدود؛ لا تُنشر بياناته أو إيصالاته. نُفذت الحركة المحددة لاحقًا بعد استيفاء البوابات وتأكيد المالك عند الحفظ كما هو موثق أدناه، واكتملت لاحقًا دورة وصول استخراجها إلى Desktop ضمن حدود الدليل أدناه.

## تقدم بوابة الاستعادة والاحتفاظ قبل الحركة

اعتمد المالك نطاقًا منفصلًا لفحص BAK موجود واستعادته إلى قاعدة جديدة وملفي بيانات وسجل جديدين داخل ضيف الاختبار فقط، دون استبدال المصدر أو إصلاحه. توقفت الجولة الأولى قبل إنشاء الهدف بسبب اختلاف بصمة مقارنة؛ بقي تقريرها محفوظًا. أثبت تحليل محلي مستقل تطابق بصمات الجداول الصحيحة، وأعاد إنتاج اختلاف فك ترميز UTF8 دون BOM باستخدام ترميز Windows القديم. كان العيب في مساعد المقارنة، وليس دليلًا على تغير بيانات المصدر.

صُحح المساعد بتحديد UTF8 صراحة وإضافة تحقق مستقل من بصمة الملف ودلالته قبل الاتصال. نجحت الجولة R2 المعتمدة فعليًا: استعادة منفصلة وCHECKDB بلا صفوف أخطاء، وتطابق الجداول الإحدى عشرة بين خط الأساس والمصدر قبل الاختبار وبعده والقاعدة المستعادة. طابقت ملفات الهدف النطاق المعتمد. لم تُنفذ كتابة إلى المصدر.

نُسخت BAK نفسها بعد النجاح إلى مجلد مضيف مستقل كان فارغًا، باستخدام وسيلة النسخ الحالية فقط. طابق الحجم وSHA-256 ما سجله تقرير الاستعادة قبلها وبعدها؛ بقي أصل الضيف وقاعدة الفحص محفوظين. هذا احتفاظ خارج VHDX على المضيف نفسه، وليس نسخة خارج المضيف أو استعادة نظام ERP كامل. غياب backup checksums يبقى قيدًا ظاهرًا.

فشل اختبار مساعد PowerShell محلي بسبب سياسة تشغيل ملفات السكربت؛ لم تُغيّر السياسة أو يُتجاوز الرفض، ولم يُحتسب الاختبار نجاحًا. مراجعة الصياغة والتحليل المحلي منفصلان عن تنفيذ المالك الفعلي في الضيف. نجحت إعادة فحص SELECT حديثة قبل الحركة، ونُقل تقريرها الأصلي وطابقت بصمته والجداول الإحدى عشرة تقرير الاستعادة قبل التنفيذ؛ كان أي اختلاف سيوقف الصرف. جميع الأصول والبصمات وأسماء الأجهزة والقواعد والمسارات والأرقام والصور الخاصة تبقى محليًا، خارج GitHub وCI.

## الحركة المحددة والاستخراج والاستيراد وإعادة التشغيل — مكتملة ضمن المختبر

بعد مطابقة خط الأساس الحديث والاستعادة والاحتفاظ، فُتح البرنامج المثبت داخل ضيف الاختبار؛ أكمل المالك المصادقة بنفسه. قُرئ آخر مستند محفوظ قبل إنشاء مسودة واحدة، وطابقت تفاصيلها نطاق الموافقة. أكد المالك حفظ المسودة المحددة عند لحظة الحفظ. نُفذ ضغط حفظ واحد فقط، ثم أُغلقت شاشة المستند وأُعيد فتح آخر مستند محفوظ؛ طابقت بياناته المسودة وبقي عدد التعديلات صفرًا. عُرض القيد المتوازن وتقرير المخزون من ERP نفسه، وطابقت النتائج التغير المحدود المتوقع دون تغير بقية أصناف الاختبار. هذا ليس تأهيل ترحيل GL النهائي أو موصل عام.

نفذ المالك مجمع R3 الموجود دون تغيير، ثم نقل الأصل المحدد بالطريقة القائمة بعد تعثر النسخ الآلي؛ بقي التعثر موثقًا ولم تتغير مشاركة أو شبكة أو خدمة أو صلاحية. طابقت بصمة الملف على المضيف البصمة المستقلة الصادرة من الضيف. تحقق المسار الموجود من الملف، وقارن فحص مستقل نطاق الجداول مع baseline: تغيرت فقط الصفوف والحقول المحدودة المرتبطة بالحركة المأذونة. لا يثبت ذلك ثبات هوية الأصناف أو اكتمال دليل المصدر العام.

أعيد تثبيت ملفات تشغيل R2 الثلاثة عشر ومحركي التشغيل. اختير الملف الجديد من نافذة النظام الأصلية في Electron، وأدخلت بصمته المستقلة ثم ظهرت المعاينة قبل النشر. نُفذ تأكيد استيراد واحد؛ عرضت الواجهة نجاح الحفظ وملاحظة تاريخية رابعة. نجحت سبع مجموعات تحقق محلية مستقلة، تشمل كامل صفوف وقيم التاريخ السابق، والمراجع القديمة، وزيادة الجيل مرة واحدة والقيم المتوقعة وحدث applied واحد فقط. بقي إجمالي اللقطة ثابتًا عند البحث، وأمكن فتح الملاحظة السابقة والعودة للأحدث. روجع Light/Dark بصريًا؛ ليست مراجعة تباين شاملة جديدة.

جُرب replay للأصل الأحدث وأصل أقدم عبر عامل Node مستقل، لا عبر زر الواجهة؛ كانا replay بلا تغيير أو تراجع للرأس. بقيت ملفات الحزمة وأصول المصادر دون تعديل. أُغلقت جلسة Electron الصحيحة، ثم شغّل المالك المشغّل العادي الحارس من جلسته دون رفع صلاحيات. أنشأ نافذة حقيقية ظاهرة، مع sandbox وcontextIsolation، ودون Node integration أو وضع qualification. أثبت فحص قراءة مستقل تطابق الرأس والتاريخ والأحداث والتفضيلات وبصمات الحزمة بعد إعادة التشغيل: لا seed أو استيراد جديد. أكدت Computer Use عرض الملاحظة الرابعة والقيم والتفاصيل وسياق المصدر في النافذة الجديدة، وتُركت للمراجعة.

نفذ المالك المصادقة والمجمع والنقل وتشغيل التطبيق من جلسته؛ نفذت Computer Use الحركة المأذونة بعد تأكيد الحفظ والاختيار والمعاينة والاستيراد والفحص المرئي؛ نفذت أدوات Node الفحوص المستقلة والتكرار وإعادة قراءة الحالة عبر Application Service. لا يُعد ذلك قبولًا بشريًا مستقلًا لدورة التحديث كاملة أو A16 أو Narrator.

بقيت الجولات والإخفاقات الأصلية ورفض سياسة السكربت محفوظة، مع أصول الضيف وBAK وقاعدة الاستعادة. لا تُنشر أرقام المستندات أو قيم الأصناف أو أوقات الالتقاط أو أسماء الأجهزة أو المسارات أو البصمات أو الإيصالات أو الصور الخاصة. نجحت CI العامة وحدود الواجهة على Windows وUbuntu للرأس التوثيقي النهائي للمنتج de1d5da؛ تبقى مجموعات runtime الخاصة خارج CI العام. PR المنتج وPR الأدلة ما زالا Draft دون دمج.
