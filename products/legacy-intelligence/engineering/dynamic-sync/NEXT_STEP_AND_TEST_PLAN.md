# Recommendation, approvals and next test plan

2026-10-25 · [التصميم المقترح](ONE_WAY_SYNC_PROPOSAL.md) · **خطة فقط؛ لا موصل أو migration أو اختبار جديد منفذ**.

## الإجابات التنفيذية

1. **الأساس مناسب للتوسع**: Products عامة واللقطات منفصلة، و staging/commit/reader والتدقيق قابلة لإعادة الاستخدام. V1 لا يصبح عامًا بمجرد تغيير رقم 5.
2. نعيد استخدام Canonical/Decimal، buffered/batched connector API، ImportOrchestrator، SQLite history/checkpoints/fingerprints، audit و query scopes. لا نزيل حراس العينة أو نمزج المصدر التاريخي بالحي.
3. **أصغر خطوة حقيقية:** اعتماد عقد full product-catalog capture وهوية/اكتمال/غياب، ثم تفويض harness اصطناعي مستقل يثبت الإضافة والتعديل والغياب والتكرار والتاريخ باستخدام APIs الحالية. لا يبدأ باقتناء ERP أو حساب مخزون عام.
4. **ملفات كاملة وتشغيل يدوي أولًا**. قارئ DB مباشر يأتي بعد تحديد المصدر وموافقة المورد وصلاحيات قراءة حقيقية. لا scheduler أو CDC الآن.
5. دعم Ibdaa أو 5,000 صنف أو متجر غير مؤهل. لكل مورد/إصدار mapping مصرح ومختبر، لا افتراض أن ملفًا صالحًا شكليًا صحيح المعنى.

## معلومات ما قبل الموصل الحقيقي

| المجال | المتكامل بلس | إبداع سوفت |
| --- | --- | --- |
| المنتج والتخزين | نعرف نسخة المختبر فقط؛ نحتاج نسخة العميل ومخططها و DB/driver ودعم المورد | المنتج والإصدار ونوع DB/API والتخزين غير مؤهلة؛ لا نفترض SQLServer |
| هوية الصنف | استقرار المفتاح، ومتى يتغير i_code؛ معنى SKU/name/unit/active/delete | تعريف الحقول والمفاتيح وتغيير/دمج/إعادة استخدام الرموز من أدلة الإصدار |
| full export | آلية رسمية أو قراءة مصرح بها، scope و filters و counts واتساق ونهاية التصدير | خيارات تصدير/نسخة مدعومة؛ تقرير صفحة ليس مجموعة كاملة |
| كمية ومال لاحقًا | تعريف الرصيد وزمنه ومخزنه وفرعه وعملته وتكلفته وإلغائه | نفس الأسئلة دون افتراض معنى من اسم جدول مشابه |
| متابعة التغير | keys/updatedAt/sequence/soft-delete/feed، إن ثبتت؛ صلاحيات و retention | دليل وجود API/feed ودلالاته، لا افتراضه |
| تفويض وخصوصية | إذن المالك/المورد والاستخدام والنقل والاحتفاظ وأقل صلاحية | تفويض المصدر نفسه؛ الأرشيف العائلي ليس بيانات العميل المحتمل |

نجاح حساب مالك أو sysadmin سابقًا لا يؤهل قارئًا حيًا. يلزم منع INSERT/UPDATE/DELETE/DDL/EXEC غير المصرح، وإدارة أسرار محلية و TLS/driver واتساق قراءة دون تعطيل ERP. إنشاء حساب/grant أو تغيير شبكة/عزل أو تفعيل CT/CDC أعمال منفصلة تحتاج موافقة؛ لا تنفذ في discovery.

## Test plan

الحالات التالية **غير منفذة**. تتطلب ملف harness/test جديدًا في نطاق تطوير معتمد، دون تغيير كود المنتج أو موصل جديد أو حراس V1 أو Preview1. نعرضها للموافقة قبل كتابتها كما اشترط المؤسس.

| ID | المدخل والعمل الاصطناعي | المتوقع وحدود الإثبات |
| --- | --- | --- |
| T01 | baseline يحوي A/B ثم capture أحدث يحوي A/B/C عبر APIs الموجودة | عدد 2→3 وهوية جديدة، baseline يبقى 2؛ ليس موصل ERP |
| T02 | stableID لـ A مع تغيير name/SKU في capture جديد | نسخة حالية محدثة وتاريخ قديم؛ لا جعل SKU هوية ثابتة |
| T03 | ملف V1 اصطناعي 4 ثم 6 مع shape/rowCount صحيحين | رفض الحارس الحالي قبل promotion؛ لا نصنع V1 ديناميكيًا بإزالته |
| T04 | غياب B من capture أحدث كامل لنفس scope | اختبار التخزين كما هو، وتحديد متطلبات absence في عقد لاحق؛ لا تسمية deleted |
| T05 | partial/truncated أو scope مختلف أو zero غامض | إظهار أن store وحده لا يعرف full؛ تطبيق رفض admission لاحق يحتاج تطويرًا معتمدًا |
| T06 | replay ثم oldknown ثم sameID/different-content | لا duplicate/currentrollback؛ conflict للهوية المتضاربة وتاريخ محفوظ |
| T07 | شركتان برموز متطابقة، rename/reuse/epoch reset | اختبار namespace وعدم دمج الغامض؛ الفجوة تسجل إن لم يدعمها العقد الحالي |
| T08 | close/reopen وتدقيق و batch error قبل commit | لا partial publication، وفحص current/history؛ لا DDL جديدة أو ERP |

لا نكمل T04/T05/T07 بسلوك غير موجود أو fake assertion أو تجاوز validator. harness يختبر الموجود ويكشف النقص. بعد اعتماد العقد الجديد تُضاف اختبارات admission/absence ثم تنفيذها بموافقة تطوير مستقلة.

## استمرار Windows Desktop دون قيد العينة

يستمر التخطيط ونظام التصميم وتدفقات المصدر واللقطة والفرق والتعافي. تؤجل bindings التي تفترض خمسة صفوف أو profile ثابتًا؛ تستهلك الواجهة capabilities و source scope و capture status وعددًا متغيرًا وصفحات عبر application contract. لا استيراد v1-inventory داخل renderer ولا اتصال SQLite مباشر.

تطوير UI اصطناعية لاحقًا ممكن بتفويضه، لكنه ليس موصلًا حقيقيًا. latest/historical/missing/unavailable حالات ظاهرة؛ لا فرز صفحة أولى كأنها المجموعة كلها. مقارنة الأرصدة ليست سجل أحداث أو إثبات حذف. لا يؤجل عقد الهوية والاكتمال إلى ما بعد واجهة جميلة.

بوابات Windows المدعوم و ACL/Defender والإنسان المستقل والنسخ المشفر خارج المضيف تبقى منفصلة كما في [PR12](https://github.com/elias-mujally/dbl-products-memory/pull/12). تعميم البيانات أو واجهة جديدة لا يغلقها.
